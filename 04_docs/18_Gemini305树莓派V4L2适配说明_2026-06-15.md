# Gemini 305 树莓派 V4L2 适配说明 2026-06-15

## 1. 适配范围

本次只覆盖树莓派发送端一路 Orbbec Gemini 305 RGBD 发送：

```text
发送端：raspberrypi-01 / berry-desktop / 192.168.66.210
接收端：192.168.66.196
相机：Orbbec Gemini 305
USB ID：2bc5:0840
序列号：CV2R46P00091
发送端 key：raspberrypi-01_cam01
```

## 2. 官方资料结论

官方资料显示 Gemini 305 的产品规格上限为：

```text
Depth：最高 1280x800@30
Color：最高 1280x800@60
```

资料入口：

```text
https://www.orbbec.com/gemini-305/
https://github.com/orbbec/OrbbecSDK_v2
```

Orbbec SDK 支持列表显示 Gemini 305 在 SDK v1 中不支持，推荐使用 Orbbec SDK v2。当前工程仍链接旧的 Orbbec SDK v1.x，因此在树莓派上用 SDK 路径枚举该相机会出现 `devices=0`。为了先完成现场发送，本次新增 V4L2/UVC 采集后端，不改接收端协议。

## 3. 实际枚举结果

现场设备实际可用节点：

```text
Depth：/dev/video0  Z16 320x200@30
RGB：  /dev/video6  MJPG 1280x800@30
```

当前选择档位：

```text
RGB：   1280x800@30 MJPG -> H.264(x264enc) 6Mbps
Depth： 320x200@30 Z16 -> zlib
曝光：  手动曝光，exposure=312，gain=80
```

## 4. 代码改动

发送端配置结构新增字段：

```text
capture_backend
rgb_device_path
depth_device_path
device_model
depth_scale
```

新增 `capture_backend=v4l2` 后，发送端可直接从 Linux V4L2 节点采集 RGB 和 Depth，不再依赖 Orbbec SDK v1 枚举该相机。V4L2 后端复用原有发送协议：

```text
RGB：MJPG 校验 -> H.264 编码 -> TCP media packet
Depth：Z16 原始帧 -> zlib 压缩 -> TCP media packet
Heartbeat/status：保持原协议
camera_announce：标记 source=v4l2_uvc，calibration.available=false
```

时间戳策略：

```text
timestamp_us：使用 V4L2 buffer timestamp
system_timestamp_us：VIDIOC_DQBUF 后立即取发送端系统时间
```

说明：V4L2/UVC 路径当前不能提供 Orbbec SDK v2 的完整标定、设备内同步和 Gemini 305 专有 metadata。如果后续要做更严格的 RGB/Depth 标定或设备级 metadata，应迁移到 Orbbec SDK v2。

## 5. 配置文件

当前配置文件：

```text
06_configs/sender_raspberrypi-01_gemini305_v4l2.json
```

关键配置：

```text
sender_id: raspberrypi-01
camera_id: cam01
capture_backend: v4l2
rgb_device_path: /dev/video6
depth_device_path: /dev/video0
rgb_profile: 1280x800@30 mjpg
depth_profile: 320x200@30 z16
rgb encoder: x264enc, 6000000bps
color_controls: auto_exposure=false, auto_exposure_priority=0, exposure=312, gain=80
hotplug.enabled: false
```

## 6. 运行方式

手动校验配置：

```bash
./12_build/bin/gemini_sender --config 06_configs/sender_raspberrypi-01_gemini305_v4l2.json --validate-config
```

无发送采集测试：

```bash
./12_build/bin/gemini_sender --config 06_configs/sender_raspberrypi-01_gemini305_v4l2.json --no-send --no-preview --run-seconds 8
```

systemd 服务现场配置：

```text
/etc/systemd/system/gemini-sender.service
ExecStart=/home/berry/Desktop/wireless_video_delivery/05_tools/sender_watchdog.sh /home/berry/Desktop/wireless_video_delivery/06_configs/sender_raspberrypi-01_gemini305_v4l2.json no-preview
SupplementaryGroups=video
Environment=GEMINI_SENDER_DEFAULT_WIFI_MIN_FREQ_MHZ=5000
```

不要在服务里默认写死 `GEMINI_SENDER_DEFAULT_WIFI_CONNECTION`。现场 AP/SSID 变化时，写死旧连接名会让 watchdog 在启动采集进程前持续失败，表现为接收端和网页预览没有树莓派画面。只有明确要求固定到某个 5GHz SSID 时，才在 systemd drop-in 或临时环境变量里设置该项。

重启服务：

```bash
sudo systemctl daemon-reload
sudo systemctl restart gemini-sender.service
```

状态查看：

```bash
./05_tools/status_sender.sh
```

`status_sender.sh` 已改为优先从当前运行中的 sender/watchdog 命令行推断实际配置，避免继续用 RK 默认配置误报 `mpph264enc`。

## 8. 注意事项

1. 该配置依赖 `/dev/video6` 和 `/dev/video0`，如果重新插拔后节点变化，需要重新确认节点并更新配置。
2. 当前 systemd 以 `no-preview` 运行；如果需要树莓派本机 OpenCV 预览，应改用不带 `no-preview` 的启动方式，并确认 DISPLAY 环境可用。
3. Gemini 305 在当前工程的 SDK v1 路径下不可用；不要把该相机切回 `capture_backend=orbbec_sdk`，除非工程已迁移到 Orbbec SDK v2。
4. 如果后续需要多相机更严格的时间戳和帧对齐，应优先评估 Orbbec SDK v2 的设备 metadata、标定数据和同步能力，V4L2 只适合先完成 UVC 采集与发送。
