# 树莓派 Gemini305 RGB 过暗排查与增益固定说明

日期：2026-06-16

## 背景

现场树莓派发送端 `raspberrypi-01` 更换为奥比中光 Gemini305 后，接收端网页预览中该路 RGB 画面明显偏暗。该发送端当前使用 V4L2 后端，一路 RGBD 发送：

```text
sender_id: raspberrypi-01
camera_id: cam01
rgb_device: /dev/video6
depth_device: /dev/video0
RGB: 1280x800@30 MJPG
Depth: 320x200@30
```

## 排查结论

该问题不是接收端网页显示问题，也不是网络或发送端卡顿导致。发送端日志显示 RGB/Depth 采集和发送稳定在 30fps 左右，且没有坏帧或发送失败：

```text
rgb_input_fps ~= 29.9-30.9
rgb_sent_packets_s ~= 29.9-30.8
rgb_preview_sent_packets_s ~= 29.9-30.8
rgb_corrupt_jpeg_frames = 0
rgb_send_failures = 0
rgb_preview_send_failures = 0
```

实际原因是 Gemini305 当前 RGB 处于手动曝光模式，原固定参数为：

```text
auto_exposure: Manual Mode
exposure_time_absolute: 312
gain: 80
```

在现场光照下，`gain=80` 对这路 Gemini305 偏低，导致 RGB 画面整体偏暗。

## 处理方式

保持手动曝光不变，不重新开启自动曝光：

```text
auto_exposure: false
auto_exposure_priority: 0
exposure: 312
```

将 RGB 增益固定为：

```text
gain: 120
```

修改文件：

```text
06_configs/sender_raspberrypi-01_gemini305_v4l2.json
```

现场树莓派本地提交：

```text
8d0d976 Fix Raspberry Pi Gemini 305 RGB gain
```

远端仓库归档提交：

```text
458651e Add Raspberry Pi Gemini305 sender config
```

远端归档提交基于 `origin/raspberrypi-latest-20260605-175527-local`，新增已验证的 Gemini305 V4L2 配置文件，并固定 `gain=120`。这样避免把树莓派现场本地分支上的分叉历史强推覆盖远端。

该配置位于树莓派发送端分支：

```text
raspberrypi-latest-20260605-175527
```

该本地分支跟踪远端：

```text
origin/raspberrypi-latest-20260605-175527-local
```

## 验证结果

运行时 V4L2 控制值确认：

```text
gain: 120
auto_exposure: 1 (Manual Mode)
exposure_time_absolute: 312
```

接收端主 RGB 预览帧实测：

```text
rgb-main size = 640x400
jpeg_bytes ~= 15474
luma ~= 144.3
mean_rgb ~= (140.1, 145.1, 149.5)
```

发送端实时日志确认：

```text
rgb_input_fps ~= 29.9-30.0
rgb_sent_packets_s ~= 29.9-30.0
rgb_preview_sent_packets_s ~= 29.9-30.0
rgb_usb_mbps ~= 41-42 Mbps
rgb_mbps ~= 6.0 Mbps
rgb_preview_mbps ~= 0.5 Mbps
depth_mbps ~= 16-17 Mbps
rgb_gain = 120
rgb_meta_actual_fps = 30
rgb_corrupt_jpeg_frames = 0
rgb_send_failures = 0
rgb_preview_send_failures = 0
depth_send_failures = 0
```

增益从 `80` 提高到 `120` 后，RGB USB 码率上升属于正常现象：画面变亮、细节和噪声增加后，MJPG 压缩数据量会增大。主发送 RGB 仍维持约 6Mbps，预览 RGB 约 0.5Mbps，未影响 30fps。

## 注意事项

1. `exposure=312` 接近 30fps 场景下更稳妥的手动曝光值。继续明显增加曝光可能影响帧周期、延迟或实际 30fps 稳定性。
2. 后续如果画面仍偏暗，优先小步调整 `gain`，例如 `100`、`120`、`140`，不要直接改回自动曝光，除非现场明确接受不同设备之间亮度随环境自动漂移。
3. 后续如果画面噪声明显或过亮，应降低 `gain`，例如回退到 `100` 或 `110`。
4. 本次只固定树莓派 Gemini305 这路 RGB 参数，不改变其他发送端相机的曝光/增益策略。
5. 树莓派工作区中同一配置文件还存在历史未提交改动，包括发送缓冲和 Web RGB 预览配置；本次归档和提交只针对 `gain=120` 这一项。

```bash

v4l2-ctl -d /dev/video6 --get-ctrl=auto_exposure,exposure_time_absolute,gain

```

接收端侧：

```bash

```
