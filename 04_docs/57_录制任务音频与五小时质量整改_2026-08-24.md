# 录制任务音频与五小时质量整改

## 1. 输入问题

本轮整改依据两份现场材料：

1. `5 小时异步录制时间测试报告（2026-08-24）`：300 个窗口调度和 NAS 发布均完成，但 182 个相机分段只有 130 个通过外部严格媒体检查。`rk3588-ubuntu_cam01` 反复出现首帧约晚 1 秒、RGB 时长偏短和 RGB/Depth 时长差超过 500 ms；网页状态在窗口边界通常仍显示上一窗口。
2. `语音录音异常问题记录（2026-08-21）`：三路全天录音中存在整段没有收到 RTP，却仍生成 900 秒全静音 `audio.opus` 并发布 ready 的伪成功；拍照事件附近也没有真实音频。

## 2. 根因

### 2.1 视频边界

发送端原先在目标帧到达后只向 GStreamer 发一次强制关键帧事件，并立即把请求视为已应用。如果硬件编码器没有响应这一次事件，只能等下一次自然 GOP，表现为首个可录 IDR 晚约 1 秒。

接收端原生 ready 只检查覆盖率、首尾延迟、最大帧间隔和时间戳倒退，没有检查 RGB 与 Depth 的媒体时长差，因此会出现本机 ready 为 `complete`、外部严格报告为 `partial` 的口径分叉。

### 2.2 音频伪成功

旧音频调度器无论是否收到真实 RTP 都按墙钟写 20 ms Opus 静音包。整段断流时仍可得到结构完整、时长正确的 Ogg 文件，旧 uploader 只校验文件存在、大小和 SHA256，无法区分真实录音与合成静音。

视频任务和全天音频原先互相独立，视频目录中没有与该任务全局时间窗口一致的音频副本。

## 3. 当前修复

### 3.1 视频

1. sender 在目标时间后每 50 ms 重试强制关键帧，直到编码输出中真正观察到 IDR 才完成请求。
2. receiver ready/meta 增加 `rgb_media_duration_us`、`depth_media_duration_us` 和 `rgb_depth_duration_delta_us`；差值超过 500 ms 时判为 `partial`。
3. Web 状态轮询由 1 秒缩短到 250 ms，降低边界显示上一状态的持续时间。
4. 仍保留约 1 秒录制准备期和统一 `target_global_us`，不降低 30 FPS。

### 3.2 视频任务音频

接收端开始每个视频切片时，通过本机 UDP `50130` 通知音频服务。音频服务复用发送端已经编码的 RTP/Opus 包，不解码、不重编码，并把同一 sender 的音频写入该 sender 同时录制的每个相机目录：

```text
<camera>/<date>/<segment>/
  rgb.mp4
  depth.mkv
  frames.csv
  meta.json
  audio.opus              # 仅在收到过真实 RTP 时存在
  audio_timing.csv
  audio_meta.json
  audio_ready.json
  recording_ready.json
```

任务音频使用视频的 `recording_session_id`、`segment_window_start_global_us` 和实际结束边界。偶发缺包用 Opus 静音补齐，保证音频时间轴不收缩。TTS/提示音继续播放，并在 `audio_meta.json.playback_events` 中记录开始/结束事件。

视频收尾最多等待音频 3 秒：

- `complete`：真实包比例至少 99%，最长连续无输入不超过 1 秒。
- `partial`：收到过真实包，但不满足完整阈值。
- `no_input`：真实包为 0；保留 meta/timing/ready，但不生成伪造的全静音 `audio.opus`。

音频异常不会使视频录制失败。无麦克风 sender 会立即写 `no_input`；已配置麦克风但音频服务失联时，等待上限后降级发布。

### 3.3 断流恢复和全天归档

三台语音 sender 恢复单次 Opus 编码双发。接收端 3 秒没有真实 RTP 时告警，5 秒时向 sender 当前状态地址的 UDP `50131` 发重建请求；sender 重启 ALSA/GStreamer 采集会话并生成新的 stream instance ID。重建接口只接受配置的接收端地址。

全天归档同样使用质量门禁。全段无输入时不再发布全静音音频文件，而是发布 `quality_status=no_input` 的证据文件。

## 4. 历史数据审计

工具：

```bash
python3 05_tools/audit_silent_audio_archive.py /path/to/nas/audio
python3 05_tools/audit_silent_audio_archive.py /path/to/nas/audio --apply
```

默认只扫描并生成全局审计清单。`--apply` 会给历史零实包片段补写：

```text
audio_valid=false
quality_status=no_input
historical_audited_receiver_us=<审计时间>
historical_audio_file_retained=true
```

历史 `audio.opus` 不删除、不移动，保留为故障证据；ready 中的文件大小和 SHA256 会同步重算。

## 5. 验收边界

本地测试覆盖 RTP 解析、时间映射、Ogg 封装、正常/部分/无输入质量判定、UDP 任务开始/结束、无输入不生成伪音频、NAS 原子发布、历史审计、receiver 降级收尾和 sender 编译。

现场部署后必须继续完成：短录制、完整 15 分钟切片和 5 小时异步复测。5 小时复测仍以外部严格媒体检查为最终口径，不能仅以 ready 文件存在作为通过。
