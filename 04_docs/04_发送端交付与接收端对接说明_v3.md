## 2. 当前端口约定

接收端需要监听：

```text
状态通道: UDP 50011
媒体通道: TCP 50010
```

配置文件位置：

```text
06_configs/sender_orangepi5pro-01.json
```

发送端会主动连接接收端：

```text
receiver.ip = 192.168.1.107
receiver.media_port = 50010
receiver.status_port = 50011
```

## 3. 状态通道

状态通道使用 UDP。

每个 UDP datagram 是一条 UTF-8 JSON 消息，发送端当前会在 JSON 后追加一个换行符 `\n`。接收端解析时可以先 trim 空白字符。

消息类型遵循：

```text
sender_hello
camera_announce
heartbeat
camera_offline
event
```

字段语义以 `04_docs/03_中间传输数据格式_v3.md` 为准。

当前实现中：

1. 启动后发送 `sender_hello`。
2. RGB 和 Depth 都拿到帧后发送 `camera_announce`。
3. 默认每 1000 ms 发送一次 `heartbeat`。
4. 编码器失败、网络失败等错误写入日志，并通过 `event` 上报。

## 4. 媒体通道

媒体通道使用 TCP。TCP 流中连续发送多个媒体 packet。

每个 packet 结构：

```text
固定头 94 字节
sender_id bytes
camera_id bytes
codec_or_compression bytes
payload bytes
```

接收端需要循环读取：

1. 先读取 94 字节固定头。
2. 校验 magic、header_version、header_size。
3. 根据 `sender_id_len`、`camera_id_len`、`codec_len` 读取 3 段字符串。
4. 根据 `payload_size` 读取 payload。
5. 处理完一个 packet 后继续读下一个 packet。

## 5. 固定头格式

固定头使用小端序。

```text
offset  size  type    field
0       4     uint32  magic
4       2     uint16  header_version
6       2     uint16  header_size
8       1     uint8   stream_type
9       1     uint8   reserved0
10      4     uint32  flags
14      2     uint16  sender_id_len
16      2     uint16  camera_id_len
18      2     uint16  codec_len
20      8     uint64  frame_id
28      8     uint64  timestamp_us
36      8     uint64  system_timestamp_us
44      8     uint64  pair_id
52      4     uint32  width
56      4     uint32  height
60      2     uint16  pixel_format
62      8     uint64  payload_size
70      8     uint64  uncompressed_size
78      16    bytes   reserved
```

固定值：

```text
magic = 0x33565747
magic bytes = 47 57 56 33
magic ascii = "GWV3"
header_version = 1
header_size = 94
```

## 6. 枚举值

`stream_type`：

```text
1 = rgb
2 = depth_raw
```

`pixel_format`：

```text
1 = encoded_video
2 = depth_u16
```

`flags`：

```text
bit 0 = key_frame
bit 1 = dropped_before
bit 2 = end_of_segment_hint
bit 3 = has_system_timestamp
```

当前实现会设置 `has_system_timestamp`。

## 7. RGB Payload

RGB packet：

```text
stream_type = 1
pixel_format = 1
codec_or_compression = h264
payload = H.264 byte-stream / AU
```

发送端当前编码路线：

```text
Orbbec RGB MJPG -> OpenCV decode BGR -> GStreamer mpph264enc -> h264parse -> TCP media packet
```

接收端建议：

1. 按 H.264 Annex B byte-stream 处理。
2. 录制时优先直接封装到 MP4/MKV，不要重编码。
3. 预览时再解码。

## 8. Depth Payload

Depth packet：

```text
stream_type = 2
pixel_format = 2
codec_or_compression = none
payload = uint16 depth_raw 一整帧
uncompressed_size = payload_size
```

当前实测规格：

```text
width = 640
height = 400
payload_size = width * height * 2 = 512000 bytes
depth_scale = 1
```

Depth 帧必须按 `uint16 little-endian` 解析。

`depth_scale` 由 `camera_announce.depth_profile.depth_scale` 提供。

## 9. 接收端最小实现建议

接收端首版可以先实现以下最小闭环：

1. UDP `50011` 打印并保存状态 JSON。
2. TCP `50010` accept 一个发送端连接。
3. 按 94 字节固定头解析媒体 packet。
4. 校验 `sender_id=orangepi5pro-01`、`camera_id=cam01`。
5. RGB payload 写入临时 `.h264` 文件，验证可被 FFmpeg 解码。
6. Depth payload 按帧写入临时 raw 文件，或写入 MKV/自定义无损容器。
7. 根据 `frame_id`、`timestamp_us` 记录逐帧索引。

## 10. 发送端运行方式

构建：

```bash
cmake -S . -B 12_build
cmake --build 12_build -j4
```

配置校验：

```bash
./12_build/bin/gemini_sender --config 06_configs/sender_orangepi5pro-01.json --validate-config
```

本机采集验证，不发送、不预览：

```bash
./12_build/bin/gemini_sender --config 06_configs/sender_orangepi5pro-01.json --run-seconds 5 --no-preview --no-send
```

后台启动：

```bash
./05_tools/start_sender.sh
```

状态查看：

```bash
./05_tools/status_sender.sh
```

停止：

```bash
./05_tools/stop_sender.sh
```

## 11. 已知限制

1. 传输协议是当前首版约定：状态 UDP、媒体 TCP。文档原需求没有写死协议，后续可替换为 SRT/RTP 等。
2. 当前只实现 `depth_compression=none`，尚未实现 LZ4/Zstd。
3. 当前 RGB 输入使用相机 MJPG，再硬编成 H.264；还没有做 1080p profile 实测。
4. 当前只按一台相机 `cam01` 配置验证。
5. 接收端未启动时，发送端会继续采集，但媒体 TCP 会报 `Connection refused` 并周期重试。
6. Orbbec SDK 停流时会输出若干 USB timeout warning，当前观察为 SDK 退出阶段日志，不影响本次采集验证结果。
