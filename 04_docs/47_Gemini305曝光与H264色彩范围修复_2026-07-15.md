# Gemini305 曝光与 H.264 色彩范围修复

日期：2026-07-15

## 1. 问题现象

`orangepi5pro-d12a4719_cam01` 的 Gemini305 RGB 画面反复出现过亮、白部扩张和灰蒙观感。仅调整曝光、增益、亮度和 gamma 无法稳定复现 6 月 18 日的录制观感。

## 2. 6 月 18 日的真实基线

不能只看当天最后一次 Git 配置。6 月 18 日 `raspberrypi-01_cam01` 使用的是同一台相机：

```text
model:  Orbbec Gemini 305
serial: CV2R46P00091
RGB:    1280x800@30 MJPG
```

当天较早实际录制的 `frames.csv` 连续记录为：

```text
rgb_auto_exposure = 0
rgb_exposure_us    = 156
rgb_gain           = 16
rgb_actual_fps     = 30
```

当天 17:35 的后续配置提交 `a95252f` 已将手动曝光改为 `312`，现场用户确认本次要恢复的是该后续档位。因此当前最终配置为：

```text
rgb_auto_exposure = 0
rgb_exposure_us    = 312
rgb_gain           = 16
rgb_actual_fps     = 30
```

当天的 RGB MP4 位流元数据为：

```text
color_range = pc/full
color_space = smpte170m (BT.601)
```

本次用历史录制文件确认增益、帧率和色彩基线，曝光值则按用户确认的后续 `312` 档位恢复。

## 3. 根因

### 曝光基线已偏离

修复前 SDK 自动曝光的帧 metadata 已达到：

```text
exposure = 301
gain     = 46
```

自动曝光下的增益已升到 `46`，明显高于目标手动档位 `312/16`，会直接增加高光溢出。

### MPP 转码丢失 JPEG 色彩范围

Gemini305 MJPEG 解码后是 full-range YUV。旧树莓派路径使用 `jpegdec + videoconvert + x264enc`，输出 H.264 正确包含 full-range/SMPTE170M 信息。

Orange Pi 当前使用 `mppjpegdec + mpph264enc`，MPP 输出 H.264 的 VUI 中没有写入色彩范围和矩阵。`ffprobe` 显示四项均为 `unknown`，接收端 FFmpeg 和浏览器就会按 limited-range 默认解码，造成白部扩张和对比度偏差。

### 已否决的方案

曾尝试在 `mppjpegdec` 和 `mpph264enc` 之间插入 `videoconvert`。实机出现：

```text
CPU ~= 135%
RGB encode ~= 17-19 ms/frame
encoder lag ~= 500-580 ms
RGB output ~= 0-2 packets/s
```

该路径会破坏 30 FPS 低延迟主链路，已完整撤销。

## 4. 修复内容

### 发送端

`06_configs/sender_orangepi5pro-d12a4719_gemini305.json` 固定为：

```json
{
  "auto_exposure": false,
  "exposure": 312,
  "gain": 16,
  "brightness": 0,
  "contrast": 50,
  "saturation": 64,
  "gamma": 300,
  "backlight_compensation": 3,
  "auto_white_balance": true,
  "auto_exposure_priority": 0,
  "power_line_frequency": 3
}
```

亮度、对比度、饱和度、gamma 和背光补偿使用当前 SDK 2.8.6 的设备默认值，避免旧调试值残留。

### 接收端

新增按 camera key 配置：

```json
"rgb_h264_full_range_camera_keys": [
  "orangepi5pro-d12a4719_cam01"
]
```

仅对该相机生效：

1. RGB 录制继续 `-c:v copy`，通过 `h264_metadata` 位流过滤器补写 `full-range + matrix_coefficients=6`，不重编码。
2. RGB recovery 重封装使用相同 VUI 修正，防止修复文件再次丢失色彩范围。
3. FFmpeg JPEG 预览显式使用 `full-range + SMPTE170M`。
4. WebCodecs 预览从接收端状态中读取 `rgb_h264_full_range=true`，按相同范围和矩阵解码。
5. 录制 `meta.json` 增加 `rgb_h264_full_range`，便于下游审计。

未列入配置的其他相机保持原有行为。

## 6. 运行边界

手动 `312/16` 是可重现的固定基线，不会随环境光自动变化。如果现场照明强度与 6 月 18 日不同，整体亮度也会不同；后续如需改亮度，应在保持 H.264 色彩范围修正的前提下单独调整 exposure/gain，不再使用 brightness/gamma 掩盖位流元数据问题。
