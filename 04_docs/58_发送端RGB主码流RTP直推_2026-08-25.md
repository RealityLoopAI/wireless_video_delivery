# 发送端 RGB 主码流 RTP 直推

日期：2026-08-25

## 目标

让指定发送端停用原有 receiver/NAS 发送程序，只采集一路 RGB，并把已经编码好的 H.264 主码流通过 RTP/UDP 直推给下游设备。

## 实现

- 每个相机新增可选 `rgb_rtp_output` 配置。
- RTP 模块复用相机的硬件 H.264 编码结果，不重复打开相机，也不增加第二次编码。
- 独立 `GstH264RtpSender` 使用持久 GStreamer pipeline：`appsrc -> queue -> h264parse -> rtph264pay -> udpsink`。
- `appsrc` 和 queue 使用各 8 个 access unit 的有界背压队列，不丢弃已经编码的 H.264 P 帧，避免破坏帧间参考链。
- UDP 发送缓冲提高到 `4 MiB`，吸收无线链路的短时调度抖动；持续拥塞时背压采集侧，而不是从编码结果中间任意丢帧。
- RTP packetizer 不随原媒体链路状态重建，避免 SSRC、序号和 RTP 时间轴被周期性重置。
- RTP pipeline 报错后释放并在下一帧自动重建，避免一次网络错误造成永久停流。
- `rtph264pay` 使用动态 payload type 和 90 kHz H.264 RTP 时钟，`config-interval=1` 周期性发送 SPS/PPS。
- `--no-send` 会同时关闭 RTP 直推，保持命令语义一致。
- 热插拔自动生成的额外相机不会继承相同 RTP 端点，避免多路码流混入同一 UDP 端口。

配置示例：

```json
"rgb_rtp_output": {
  "enabled": true,
  "host": "192.168.66.226",
  "port": 5600,
  "payload_type": 96,
  "mtu_bytes": 1200
}
```

当前设备使用独立配置 `sender_orangepi5pro-f022c4_rtp_only.json`：

- 设备：`orangepi5pro-f022c4`，当前地址 `192.168.66.112`。
- 输入：`cam01` RGB `1920x1080@30 MJPEG`。
- 输出：硬件 H.264，约 `12 Mbps`，RTP/UDP 到 `192.168.66.226:5600`。
- 禁用项：Depth、GWHP TCP、status、CLOCK_SYNC、本机预览、Web 预览、录制缓冲和热插拔扩展相机。
- 服务：`gwv3-rgb-rtp-orangepi5pro-f022c4.service`，已启用开机自启。
- 原服务：`gwv3-gemini-sender.service`，已停止并禁用，避免重复打开相机。

## 降级行为

RTP/UDP 为无连接、无确认发送。目标设备未启动或中途断开时，sender 继续正常运行；恢复接收后最多等待约一个 GOP 获取下一组 SPS/PPS/IDR。该 RTP-only 模式不发送 GWV3 媒体、状态和 CLOCK_SYNC，也不携带 `global_timestamp_us`；如需录制、多机统一时间轴或帧级元数据，应恢复原发送服务。

## 验证

- 本机和 RK3588 实机构建通过。
- 本机和 RK3588 sender 测试均为 `4/4` 通过。
- 配置回归测试覆盖合法端点、非法主机名和非法 RTP payload type。
- 实机仅运行一个 `gemini_sender`，无 TCP 媒体连接，RGB 输入维持约 `30 FPS`。
- 源端抓包 10 秒：`299` 个 RTP marker 帧，`29.90 FPS`，有效载荷约 `12.05 Mbps`，单一 SSRC。
- 接收设备需允许 `UDP 5600`，并通过 SDP 指定 H.264、payload type `96` 和 `90000 Hz` 时钟。

### 错帧修复

首版 RTP 队列允许丢弃已经编码的旧帧。现场 20 秒抓包观察到约 5 次 RTP 时间戳跨过一个完整帧周期；被丢弃的 P 帧仍可能是后续 P 帧的参考帧，因此接收画面会短暂出现预测错误。当前版本改为有界背压、不丢编码帧，并扩大 UDP 发送缓冲。接收端仍可在完成解码后丢弃过期图像，但不能在 H.264 解码前任意丢包或丢 P 帧。

修复后实机连续抓包 30 秒：

- RTP 包 `39486` 个，序号缺失 `0`，重复 `0`。
- marker 帧 `900` 个，帧率严格为 `30.000 FPS`。
- 连续帧的 RTP 时间戳增量全部为 `3000`，没有整帧跳过。
- IDR `30` 个，约每秒一个；SSRC 数量为 `1`。
- IP 包长度 `42..1228` 字节，IP 分片数为 `0`。
- 有效载荷约 `12.17 Mbps`。

## 服务切换

当前 RTP-only 服务：

```bash
sudo systemctl status gwv3-rgb-rtp-orangepi5pro-f022c4.service
sudo systemctl restart gwv3-rgb-rtp-orangepi5pro-f022c4.service
sudo systemctl stop gwv3-rgb-rtp-orangepi5pro-f022c4.service
```

需要恢复原 receiver/NAS 发送模式时：

```bash
sudo systemctl disable --now gwv3-rgb-rtp-orangepi5pro-f022c4.service
sudo systemctl enable --now gwv3-gemini-sender.service
```
