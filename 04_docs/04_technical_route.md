# 技术路线说明

## 1. 当前实现路线

发送端：

1. 从 Gemini 相机采集 RGB 帧  
2. 使用 H.264 低延迟参数编码  
3. 分包成 RTP/UDP 发送到接收端

接收端：

1. 监听 UDP 端口  
2. RTP 重组与抖动处理  
3. H.264 解码后显示实时画面

## 2. 当前工程特点

- 单路实时优先，队列满时丢旧帧保实时
- 发送端支持自动重连与状态统计
- 接收端已加重排窗口与 depacketizer 缓冲保护（Linux主线）

## 3. 为什么提供两个接收端包

- `03_receiver_linux`: 跟 Linux 发送端同类环境，便于调试压测
- `02_receiver_windows`: 适配 Windows 落地部署，带 PowerShell 启停脚本

## 4. 已知边界

- 当前发送端架构为单相机
- 当前接收端核心是软件解码
- 多设备并发时主要瓶颈在接收端解码能力而非 5GHz 网络

## 5. 后续演进建议

1. 接收端切硬件解码（优先级最高）  
2. 发送端多相机架构重构  
3. 逐步向标准监控协议与 VMS 架构演进
