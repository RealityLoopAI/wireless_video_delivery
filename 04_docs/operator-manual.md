# 现场运维操作手册

更新时间：2026-09-07  
适用对象：不负责开发、只负责现场开机、查看和录制的人员

## 1. 只记住这四句话

1. **先开 NAS，再开 Receiver，最后开 Sender。**
2. **网页看到所有相机在线后再点“开始”。**
3. **录制中不要拔线、断电、切网络或连续点击按钮。**
4. **点“停止”后要等收尾和 NAS 文件完成，再断电。**

不知道某个设置的作用时不要改。网页预览短暂卡顿不一定代表录像坏了，先按本手册检查。

## 2. 认识设备

| 设备 | 怎么认 | 需要连接什么 |
| --- | --- | --- |
| NAS | 保存录像的存储设备 | 电源、网线 |
| Receiver | 接收电脑，提供网页 | 电源、网线 |
| Sender | 每台连接一台或多台相机的小电脑 | 电源、相机 USB、Wi-Fi |
| 操作电脑 | 现场人员使用的电脑 | 与 Receiver 同一局域网 |

不要把相机直接接到 Receiver。不要把 Receiver 或 NAS 接到访客隔离网络。

## 3. 每次开机

### 第一步：检查接线

逐项确认：

- [ ] NAS 电源已接，网线已接。
- [ ] Receiver 电源已接，网线已接。
- [ ] 每台 Sender 电源已接。
- [ ] 每个相机已经插入对应 Sender 的 USB 3.x 接口。
- [ ] 路由器/AP 已开机。
- [ ] 没有松动、转接过多或明显损坏的 USB 线。

### 第二步：按顺序开机

1. 打开 NAS，等待 **2 分钟**。
2. 打开 Receiver，等待 **2 分钟**。
3. 打开全部 Sender，等待 **2 分钟**。

Sender 和 Receiver 的服务会自动启动，不需要双击桌面脚本，也不要重复启动程序。

### 第三步：找到 Receiver 地址

Receiver 使用 DHCP，IP 可能随现场网络改变。

在 Receiver 上打开终端，输入：

```bash
hostname -I
```

会看到一个或多个地址，例如：

```text
192.168.1.196
```

优先使用与操作电脑同网段的有线地址。不要使用 `127.0.0.1`，也不要照抄示例地址。

### 第四步：打开网页

在操作电脑浏览器地址栏输入：

```text
http://<Receiver实际IP>:8080
```

例如 Receiver 实际 IP 是 `192.168.1.196`，就访问：

```text
http://192.168.1.196:8080
```

当前网页不需要账号、密码或访问令牌。

## 4. 看懂网页

网页顶部会显示类似：

```text
5/5 有画面 · 5 在线 · 空闲
```

各状态含义：

| 页面文字 | 含义 | 该怎么做 |
| --- | --- | --- |
| `LIVE` / 在线 | 相机正在发送数据 | 正常 |
| `WAIT` | 正在等待画面或统一录制起点 | 等待，不要重复点击 |
| `REC` / 录制 | 该路正在录像 | 正常 |
| `FINAL` / 收尾 | 正在关闭文件、写索引或发布 | 等待，不要断电 |
| `OFF` / 离线 | 该路没有新数据 | 按“相机离线”处理 |
| 空闲 | 当前没有录像 | 可以开始新任务 |
| 状态暂存 | Receiver 管理接口短时没有响应，页面显示缓存 | 先等 10 秒，不要连续操作 |

主画面大窗口用于观察，右侧是其他相机。点击其他相机的小画面可切换主画面。

预览只用于监控，不是最终录制文件。某个预览窗口短暂卡住时，先看该路是否仍为在线、`Last media` 是否持续更新。

## 5. 开始录制

### 开始前必须检查

- [ ] 页面能正常打开。
- [ ] 页面相机总数与现场实际数量一致。
- [ ] 每一路显示在线，不是 `OFF`。
- [ ] 每一路 RGB 画面正常；需要 Depth 时也检查 Depth。
- [ ] 顶部显示“空闲”，没有“收尾”。
- [ ] “开始”按钮可以点击，不是灰色。
- [ ] 没有人正在插拔相机、切换 Wi-Fi 或维护设备。

### 开始操作

1. 只点击一次网页顶部的 **“开始”**。
2. 等待约 1 到 3 秒。
3. 确认所有目标相机由 `WAIT` 变为 `REC`。
4. 确认顶部显示实际录制路数，例如“5 路录制”。
5. 记录本次开始时间、任务名称和操作人。

如果某一路没有进入 `REC`，不要假装任务正常，也不要连续点“开始”。按第 11 节处理。

## 6. 录制过程中

每 15 到 30 分钟看一次网页，检查：

- [ ] 所有目标相机仍显示 `REC`。
- [ ] 在线路数没有减少。
- [ ] RGB/Depth 画面或 `Last media` 时间仍在更新。
- [ ] 没有持续显示 `receiver admin unavailable: timed out`。
- [ ] 没有设备反复离线和上线。
- [ ] NAS 和 Receiver 没有断电、掉网告警。

录制中禁止：

- 拔插相机；
- 重启 Sender、Receiver 或 NAS；
- 切换 Sender Wi-Fi；
- 修改曝光、白平衡、分辨率或帧率；
- 关闭终端里的服务；
- 连续点击开始或停止；
- 把最终目录中的文件移动、改名或删除。

只关闭浏览器网页不会停止录像。重新打开网页后应再次确认状态。

## 7. 停止录制

### 停止操作

1. 只点击一次网页顶部的 **“停止”**。
2. 等待页面从 `REC` 变成 `FINAL` 或“收尾”。
3. 继续等待，直到顶部显示“空闲”且不再显示“收尾”。
4. 不要因为按钮已经返回成功就立即断电。

“停止”表示系统接受了停止时间，不表示文件已经全部出现在 NAS。

### 确认 NAS 文件完成

打开 NAS 的最终录像目录，确认本次每路相机都有新的分片目录。每个可交付目录必须存在：

```text
recording_ready.json
```

常见文件还包括：

```text
rgb.mp4
depth.mkv
frames.csv
meta.json
calibration.json
```

只有看到 `recording_ready.json`，该目录才算完成。没有这个文件时不要交给下游，不要手工创建它。

### 能否马上开始下一次

可以在网页“开始”按钮重新可用后开始下一次。上一任务可能仍在后台向 NAS 补传，但系统会根据存储状态决定是否允许新任务。

如果“开始”按钮是灰色，说明当前不安全。等待系统恢复，不要绕过限制。

## 8. 使用物理按键的设备

只有安装了项目按键的 Sender 才适用本节。

| 操作 | 效果 |
| --- | --- |
| 长按录制键约 1 秒 | 开始该 Sender 上所有在线相机的录制 |
| 长按停止键约 1 秒 | 停止该 Sender 上所有相机的录制 |
| 长按电源键约 5 秒 | 等当前语音结束，播放关机提示，然后关机 |

注意：

1. Sender 按键只控制这台 Sender，不控制其他 Sender。
2. 请求失败、Receiver 不可达或状态正在切换时，按键不会播放成功提示音。
3. 按键触发后仍要到网页确认是否进入 `REC` 或退出录制。
4. 配有录制 LED 的设备：正常开机常亮，录制时闪烁，关机后熄灭。

## 9. 音频功能

网页右上角点击 **“音频”** 或进入 **“设置 / 状态”**，可以看到全天音频归档。

- “全部开始”：启动所有已配置 Sender 的全天音频归档。
- “全部暂停”：暂停全天音频归档。
- 视频任务内的对齐音频由录制任务管理，不要用“全天音频归档”状态判断视频是否录制成功。

当前配置不是所有设备都一定有麦克风。显示 `no input` 时先确认该设备是否本来就应该接音频设备。

## 10. 正常关机

### Sender 关机

1. 先确认该 Sender 不在录制。
2. 有项目电源键时长按约 5 秒，等待提示音和系统关机。
3. 没有项目电源键时由维护人员通过系统菜单关机。
4. 屏幕熄灭或设备完成关机后再断电。

### 整套系统关机

必须按下面顺序：

1. 停止录制。
2. 等网页不再显示 `REC` 或 `FINAL`。
3. 确认 NAS 本次目录已经出现 `recording_ready.json`。
4. 关闭全部 Sender。
5. 关闭 Receiver。
6. 最后关闭 NAS。

不要直接拉总电源。异常断电可能损坏正在写的最后一个分片。

## 11. 常见问题

### 11.1 网页打不开

按顺序做：

1. 确认 Receiver 已开机至少 2 分钟。
2. 在 Receiver 重新运行 `hostname -I`，确认 IP 是否变化。
3. 确认网址包含 `http://` 和端口 `:8080`。
4. 确认操作电脑与 Receiver 在可互相访问的局域网。
5. 换一个浏览器标签页重新打开，不要访问端口 `18080`。

仍打不开时记录 Receiver IP、时间和现场网络名称，联系维护人员。不要重装系统。

### 11.2 页面提示 `receiver admin unavailable: timed out`

1. 停止连续点击任何按钮。
2. 等待 10 秒。
3. 刷新浏览器页面一次。
4. 如果一分钟后仍持续出现，记录时间和当时是否正在录制。
5. 正在录制时不要擅自重启 Receiver，联系维护人员。

短暂提示可能只是管理接口忙，不等于主媒体已经断流。

### 11.3 页面少了一路相机

1. 等待 2 分钟，观察是否自动恢复。
2. 确认对应 Sender 有电并已连接 Wi-Fi。
3. 确认相机 USB 线没有松动。
4. 如果正在录制，先记录故障时间，不要立刻拔线。
5. 非录制状态下可重新插紧相机 USB，等待 2 分钟。
6. 仍未恢复时联系维护人员，并说明缺失的设备名称。

### 11.4 预览画面卡住

1. 看其他相机是否同时卡住。
2. 打开“设置”，看该路 `Last media` 是否持续更新。
3. 如果 `Last media` 在更新，可能只是预览链路卡顿；不要立即停止录像。
4. 如果 `Last media` 也不更新并且状态为 `OFF`，按相机离线处理。
5. 记录卡住时间，便于与录像和日志核对。

### 11.5 “开始”按钮是灰色

常见原因是 NAS 未就绪、本地存储空间不足、上一状态还在转换或录制存储门禁生效。

1. 等待 30 秒再看。
2. 确认 NAS 已开机且网线正常。
3. 确认上一任务已经停止。
4. 不要反复刷新、绕过按钮或用其他接口强行开始。
5. 仍不可用时联系维护人员。

### 11.6 点停止后 NAS 很久没有文件

1. 看网页是否仍显示“收尾”。
2. 确认 NAS 在线且网线正常。
3. 等待后台补传和校验。
4. 只认最终目录中的 `recording_ready.json`。
5. 不要进入隐藏目录取半成品，也不要手工移动文件。

数据量越大或 NAS 曾经断线，完成时间越长。

### 11.7 画面太亮、太暗或颜色不对

1. 检查镜头保护膜、镜头污渍和现场灯光。
2. 确认相机没有被遮挡或正对强光。
3. 不要现场修改曝光、增益和白平衡。
4. 截图并记录 Sender 名称、相机名称、时间和场景，交给维护人员处理。

固定采集参数是数据一致性的一部分，临时手调可能让不同批次无法比较。

### 11.8 NAS 或 Receiver 中途断电

1. 恢复供电和网络。
2. 等待 NAS 2 分钟，再等待 Receiver 2 分钟。
3. 打开网页检查所有相机。
4. 系统只恢复、修复和补传已有数据，不会自动继续旧录像。
5. 由负责人确认后重新点击“开始”，并把本次断电记入任务记录。

## 12. 什么时候必须停止操作并联系维护人员

出现任意一项时，不要继续录制新任务：

- 相机数量与任务要求不一致；
- “开始”按钮持续灰色；
- 多路相机反复上线、掉线；
- Receiver 或 NAS 反复重启；
- 页面持续一分钟以上无法读取 Receiver 状态；
- NAS 最终目录长期没有 `recording_ready.json`；
- 磁盘空间不足告警；
- 设备有异味、异常发热、风扇停转或电源不稳定；
- 画面方向、分辨率、曝光或颜色与任务要求不一致。

联系维护人员时一次提供以下信息：

```text
发生时间：
正在录制：是 / 否
Receiver IP：
网页显示的在线路数：
异常 Sender/相机名称：
页面错误原文：
是否发生断电、拔线或换网络：
现场截图：
```

## 13. 运维人员禁止事项

- 不执行 `git pull`、编译、升级或重装 SDK。
- 不修改 `/etc/gwv3/`、`06_configs/` 或 systemd 服务。
- 不在录制中重启程序或设备。
- 不把 Receiver 管理端口 `18080` 暴露到局域网或公网。
- 不删除 Receiver 本地 staging 来“释放空间”。
- 不删除 NAS 隐藏目录或手工创建 `recording_ready.json`。
- 不用预览画面替代最终文件验收。
- 不用播放器显示的标称帧率替代数据质量检查。
- 不向 Git、文档、截图或群聊发送 Wi-Fi/NAS 密码。

## 15. 给维护人员的只读检查命令

普通现场操作员不需要执行本节。维护人员进入对应设备仓库后可使用：

Receiver：

```bash
./05_tools/status_receiver.sh /etc/gwv3/receiver.json
./05_tools/gwv3_doctor.sh receiver /etc/gwv3/receiver.json
```

Sender：

```bash
./05_tools/status_sender.sh
./05_tools/gwv3_doctor.sh sender /etc/gwv3/sender.json
```

这些命令只用于查看。生产录制期间不要把启动脚本当成状态检查工具。
