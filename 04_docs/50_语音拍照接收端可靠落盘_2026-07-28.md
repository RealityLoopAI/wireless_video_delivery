# 语音拍照接收端可靠落盘

日期：2026-07-28

## 1. 需求

在 `orangepi5pro-d12a4719` 上复用已有 USB 麦克风、USB 音箱和“小环”离线语音服务：

1. 用户说出拍照命令后，由正在运行的 sender 取得目标相机下一帧 RGB。
2. 相机方向正常时保存原始 MJPEG；配置 RGB 软件旋转 180 度时，快照线程单独校正方向。
3. 图片经 receiver 留存到 NAS，不让 sender 直接访问 NAS。
4. receiver 本地可靠收到图片后立即返回 `captured`，语音播放“好的，已拍照”。
5. NAS 上传异步完成，不能阻塞采集、媒体发送、录制或语音确认。
6. 不改变现有 RGBD 录制目录和状态机；照片使用独立目录。
7. 每次语音拍照默认连续保存 3 张，采集请求间隔 0.2 秒。

## 2. 当前链路

```text
语音服务按 0.2 秒间隔写 3 个本地请求 JSON
  -> sender 选择下一帧完整原始 MJPEG
  -> 独立快照线程按配置校正 180 度方向
  -> 独立可靠 TCP 快照队列，ACK 丢失时重发
  -> receiver 独立照片队列
  -> 本地 photo.jpg + photo_ready.json + fsync + 原子任务目录
  -> UDP captured ACK
  -> 3 张全部 captured 后语音播放“好的，已拍照”
  -> 独立 photo uploader 校验大小和 CRC
  -> NAS 临时文件 + fsync + 原子重命名
```

快照使用媒体协议 `stream_type=4 (rgb_snapshot)`。`request_id` 放在：

```text
codec_or_compression=mjpeg;request_id=<request_id>
```

媒体包版本仍为 v2，没有修改原有固定包头。

## 3. 可靠性语义

`captured` 的精确定义：

1. receiver 已收到完整 JPEG。
2. JPEG SOI/EOI、大小上限通过检查。
3. `photo.jpg` 已写入并 `fsync`。
4. 带 CRC32、帧时间戳和 NAS 相对路径的 `photo_ready.json` 已写入并 `fsync`。
5. 临时任务目录已原子重命名，staging 根目录已 `fsync`。

`captured` 不表示 NAS 已上传完成。这样 NAS 断开时照片仍有 receiver 本地可靠副本，语音不需要等待 SMB 往返。

sender 在 30 秒内保留待确认请求，每秒重发一次未确认快照。receiver 对同一 `request_id` 幂等处理，并连续发送三次 ACK。队列满、格式错误或 staging 不可用时返回明确失败，不影响 RGBD 主链路。

## 4. 目录

receiver 本地 staging：

```text
/home/fz/recording_staging/.gwv3_photo_queue/<request_id>/
  photo.jpg
  photo_ready.json
```

最终 NAS：

```text
/home/fz/Desktop/nas/voice_photos/<sender_id>_<camera_id>/YYYY-MM-DD/HH-MM-SS/YYYYMMDD_HHMMSS.jpg
```

单张拍照的时间取自被选中 RGB 帧的 `system_timestamp_us`。一次三连拍共用稳定 `burst_id`，接收端以第一张有效帧确定目录和文件名前缀，三张依次使用 `.jpg`、`_001.jpg`、`_002.jpg`；即使后两张跨过整秒，也不会拆到下一秒目录。若目标秒目录已经被另一轮拍照占用，整组使用 `HH-MM-SS_001` 目录。最终 NAS 只保留 JPG，不写旁路 JSON。

## 5. 隔离边界

1. `rgb_snapshot` 不进入 Web 预览。
2. `rgb_snapshot` 不进入 `frames.csv`、MP4、MKV 或录制切片。
3. sender 使用独立 TCP 连接和有界可靠队列，不占 RGB/Depth 最新帧队列。
4. Orbbec SDK 若在 JPEG EOI 后附加零填充，sender 会在发送前剥离；receiver 也兼容旧 sender 的此类报文，JPEG 有效内容不变。
5. receiver 的 staging 写盘在独立 worker 中，不阻塞 media client thread。
6. `gwv3-photo-uploader.service` 与 `gwv3-recording-uploader.service` 分离。
7. uploader 检测 NAS 挂载；未挂载时不向空挂载点误写。

## 6. 画面方向与连拍

相机方向正常时，保存内容是相机提供的原始 MJPEG 有效字节。若 sender 的实时 RGB 配置为软件旋转 180 度，原始快照会在独立快照发送线程中解码、旋转并以 JPEG quality 95 重编码；该处理不在采集线程执行，且通过 `snapshot_orientation_applied` 标记写入接收端清单。

语音服务默认 `photo_burst_count=3`、`photo_burst_interval_seconds=0.2`。每轮生成一个稳定 `burst_id`，三个有界请求会立即写入，并分别携带 `capture_not_before_unix_us=T/T+0.2s/T+0.4s`；sender 按目标时间选择第一帧，避免请求目录扫描和 `captured` 回执耗时改变帧间隔。receiver 用 `burst_id` 把三张绑定到第一张所选目录。随后统一收集三张回执；任何一张未收到 `captured` 时都不播放成功提示，并在日志中保留每张结果和已成功数量。
