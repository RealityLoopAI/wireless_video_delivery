# 接收端运行使用手册 v3

更新时间：2026-05-11

本文档说明 Ubuntu 接收端的启动、停止、状态检查、录制控制、NAS 落盘和 Orbbec 兼容导出。

## 1. 适用范围

接收端运行在 Ubuntu x86_64 主机上，负责：

- 监听发送端 UDP 状态包和 TCP 媒体包。
- 提供 C++ 本地管理 API。
- 提供 Web 监控页面。
- 控制录制并写入 NAS。
- 将录制 segment 离线导出为下游 Orbbec 兼容交付目录。

## 2. 默认配置

配置文件：

```text
06_configs/receiver_ubuntu-01.json
```

当前默认端口：

```text
media tcp: 50010
status udp: 50011
admin http: 127.0.0.1:18080
web: 0.0.0.0:8080
```

当前默认 NAS 根目录：

```text
/home/fz/Desktop/nas
```

## 3. 一键启动、停止、状态

启动：

```bash
./05_tools/start_receiver.sh
```

停止：

```bash
./05_tools/stop_receiver.sh
```

查看状态：

```bash
./05_tools/status_receiver.sh
```

如果要使用非默认配置：

```bash
./05_tools/start_receiver.sh 06_configs/receiver_ubuntu-01.json
./05_tools/status_receiver.sh 06_configs/receiver_ubuntu-01.json
```

启动脚本会自动：

1. 检查 `cmake`、`g++`、`ffmpeg`、`python3`。
2. 编译 `gemini_receiver`。
3. 创建 Web 监控 Python venv。
4. 启动 C++ 接收端。
5. 启动 Web 监控服务。

## 4. Web 页面

默认访问：

```text
http://127.0.0.1:8080
```

页面能力：

- 查看发送端在线状态。
- 查看 RGB/Depth packet 和字节计数。
- 查看 RGB 实时预览。
- 查看 Depth 伪彩实时预览。
- 全局开始/停止录制。
- 单相机开始/停止录制。

## 7. Orbbec 兼容导出

如果下游工程师能直接读取 RGB 和 Depth 录像，推荐只导出 Orbbec 风格的 JSON/CSV/预览文件，不默认展开逐帧 PNG。

导出命令：

```bash
./05_tools/export_orbbec_delivery.py <segment_dir> --overwrite
```

示例：

```bash
./05_tools/export_orbbec_delivery.py \
  /home/fz/Desktop/nas/orangepi5pro-01_cam01/2026-05-11/180433 \
  --overwrite
```

默认输出：

```text
<segment_dir>/orbbec_delivery/<session_name>/
```

如果下游强制要求逐帧 `uint16 PNG`：

```bash
./05_tools/export_orbbec_delivery.py <segment_dir> --export-depth-png --overwrite
```

详细说明见：

```text
04_docs/07_Orbbec交付导出说明_v3.md
```

## 8. 常见问题

### 8.1 Web 页面打不开

先执行：

```bash
./05_tools/status_receiver.sh
```

确认 C++ 接收端和 Web 监控都在运行。如果管理接口不可用，查看：

```text
08_reports/receiver_logs/receiver.log
08_reports/receiver_logs/receiver_stdout.log
08_reports/receiver_logs/web_stdout.log
```

### 8.2 没有 RGB 预览

RGB 预览依赖发送端持续输出可解码 H.264 帧。接收端刚启动后需要等到新的关键帧或完整帧进入预览解码器。

### 8.3 录制目录没有 `rgb.mp4`

可能录制时长过短，或者发送端没有输出可封装的 H.264 视频帧。检查 `ffmpeg.log` 和 `rgb_debug.h264`。

### 8.4 Depth CSV 的 `pair_delta_ms` 很大

RGB 和 Depth 的 SDK timestamp 可能不是同一时间基准。后续对齐应优先使用新增的 `*_system_timestamp_us` 字段和接收端 `local_time_us`。
