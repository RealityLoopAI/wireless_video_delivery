# 接收端运行使用手册 v3

更新时间：2026-05-21

本文档说明 Ubuntu 接收端的启动、停止、状态检查、录制控制、NAS 落盘和 Orbbec 兼容导出。

## 1. 适用范围

接收端运行在 Ubuntu x86_64 主机上，负责：

- 监听发送端 UDP 状态包和 TCP 媒体包。
- 提供 C++ 本地管理 API。
- 提供 Web 监控页面。
- 控制录制并写入 NAS。
- 将录制 segment 离线导出为下游 Orbbec 兼容交付目录。

## 2. 默认配置

配置文件：

```text
06_configs/receiver_ubuntu-01.json
```

当前默认端口：

```text
media tcp: 50010
status udp: 50011
admin http: 127.0.0.1:18080
web: 0.0.0.0:8080
```

当前默认 NAS 根目录：

```text
/home/fz/Desktop/nas
```

## 3. 一键启动、停止、状态

启动：

```bash
./05_tools/start_receiver.sh
```

停止：

```bash
./05_tools/stop_receiver.sh
```

查看状态：

```bash
./05_tools/status_receiver.sh
```

如果要使用非默认配置：

```bash
./05_tools/start_receiver.sh 06_configs/receiver_ubuntu-01.json
./05_tools/status_receiver.sh 06_configs/receiver_ubuntu-01.json
```

启动脚本会自动：

1. 检查 `cmake`、`g++`、`ffmpeg`、`python3`。
2. 编译 `gemini_receiver`。
3. 创建 Web 监控 Python venv。
4. 启动 C++ 接收端。
5. 启动 Web 监控服务。

## 4. Web 页面

默认访问：

```text
http://127.0.0.1:8080
```

页面能力：

- 查看发送端在线状态。
- 查看 RGB/Depth packet 和字节计数。
- 查看 RGB 实时预览。
- 查看 Depth 伪彩实时预览。
- 全局开始/停止录制。
- 单相机开始/停止录制。

## 6. NAS 落盘目录

每段录制写入：

```text
<nas_root>/<sender_id>_<camera_id>/<YYYY-MM-DD>/<HHMMSS>/
```

典型文件：

```text
rgb.mp4
depth.mkv
frames.csv
calibration.json
meta.json
ffmpeg.log
rgb_debug.h264
depth_debug.raw
```

格式细节见：

```text
04_docs/06_接收端当前存储格式说明_v3.md
```

如果后续需要生成 RGB 坐标系下的 aligned depth，可在录制完成后运行：

```bash
python3 05_tools/align_depth_to_rgb.py <segment_dir>
```

该命令会读取同一 segment 的 `depth.mkv` 和 `calibration.json`，输出 `depth_aligned_to_rgb.mkv`。

## 7. Orbbec 兼容导出

如果下游工程师能直接读取 RGB 和 Depth 录像，推荐只导出 Orbbec 风格的 JSON/CSV/预览文件，不默认展开逐帧 PNG。

导出命令：

```bash
./05_tools/export_orbbec_delivery.py <segment_dir> --overwrite
```

示例：

```bash
./05_tools/export_orbbec_delivery.py \
  /home/fz/Desktop/nas/orangepi5pro-b439137c_cam02/2026-05-11/180433 \
  --overwrite
```

默认输出：

```text
<segment_dir>/orbbec_delivery/<session_name>/
```

如果下游强制要求逐帧 `uint16 PNG`：

```bash
./05_tools/export_orbbec_delivery.py <segment_dir> --export-depth-png --overwrite
```

详细说明见：

```text
04_docs/07_Orbbec交付导出说明_v3.md
```

## 8. 录制帧率分析

接收端录制时会按前几帧真实到达间隔估算封装帧率，并写入 `meta.json` 的 `rgb_record_fps` / `depth_record_fps`。

如果本地播放感觉帧率低，不要只看播放器显示的标称 fps，应同时分析 `frames.csv` 里的真实到达帧率。

分析命令：

```bash
./05_tools/analyze_segment_fps.py <segment_dir>
```

示例：

```bash
./05_tools/analyze_segment_fps.py \
  /home/fz/Desktop/nas/orangepi5pro-b439137c_cam02/2026-05-12/102013
```

重点看：

- `media`：文件封装后的编码、分辨率、标称 fps、码率。
- `arrival`：接收端真实收到的 RGB/Depth 帧率。
- `intervals`：帧间隔抖动，`p95` 和 `>50ms` 越大，播放观感越卡。

## 9. 常见问题

### 9.1 Web 页面打不开

先执行：

```bash
./05_tools/status_receiver.sh
```

确认 C++ 接收端和 Web 监控都在运行。如果管理接口不可用，查看：

```text
08_reports/receiver_logs/receiver.log
08_reports/receiver_logs/receiver_stdout.log
08_reports/receiver_logs/web_stdout.log
```

### 9.2 没有 RGB 预览

RGB 预览依赖发送端持续输出可解码 H.264 帧。接收端刚启动后需要等到新的关键帧或完整帧进入预览解码器。

### 9.3 录制目录没有 `rgb.mp4`

可能录制时长过短，或者发送端没有输出可封装的 H.264 视频帧。检查 `ffmpeg.log` 和 `rgb_debug.h264`。

### 9.4 Depth CSV 的 `pair_delta_ms` 很大

RGB 和 Depth 的 SDK timestamp 可能不是同一时间基准。后续对齐应优先使用新增的 `*_system_timestamp_us` 字段和接收端 `local_time_us`。

### 9.5 播放器帧率和观感不一致

接收端会按实测到达帧率封装录像，避免把十几帧的源流强行标成 30fps 导致本地播放速度异常。真实流畅度仍取决于发送端实际送达帧率。用 `analyze_segment_fps.py` 检查 `arrival fps`；如果 `arrival fps` 只有十几帧，应优先排查发送端采集、编码、Depth 压缩、预览和网络链路。
