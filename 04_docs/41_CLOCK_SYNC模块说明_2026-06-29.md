# CLOCK_SYNC 模块说明

更新时间：2026-06-29

## 目标

本模块用于给多 sender 数据集生成提供统一时间轴。receiver 作为 master clock，sender 周期性通过 UDP probe 获取相对 receiver 的时间偏移，receiver 再按 sender 上报的 offset 为收到的媒体包生成 `global_timestamp_us`。

它不是硬同步，不改变相机曝光时刻，也不改变现有 RGB/Depth 配对、TCP/UDP media 链路、GStreamer 编码路径。

## 协议

新增独立 UDP 端口，默认 `50012`。

sender 每 2 秒发送：

```json
{
  "protocol_version": "3.0",
  "message_type": "clock_sync_probe",
  "sender_id": "rk3588-ubuntu",
  "sequence": 123,
  "t1_sender_send_us": 1710000000000000
}
```

receiver 收到后立即回复：

```json
{
  "protocol_version": "3.0",
  "message_type": "clock_sync_response",
  "sender_id": "rk3588-ubuntu",
  "sequence": 123,
  "t1_sender_send_us": 1710000000000000,
  "t2_receiver_recv_us": 1710000000001200,
  "t3_receiver_send_us": 1710000000001300
}
```

sender 本地收到 response 后记录 `t4_sender_recv_us`，用 NTP 四时间戳算法计算：

```text
offset_us = ((t2 - t1) + (t3 - t4)) / 2
delay_us  = (t4 - t1) - (t3 - t2)
```

`offset_us` 表示：

```text
receiver_clock - sender_clock
```

## sender 行为

新增文件：

```text
01_sender_linux/include/gwv3_sender/clock_sync_client.hpp
01_sender_linux/src/clock_sync_client.cpp
```

特性：

1. 独立线程运行，不阻塞采集、编码和媒体发送。
2. 默认 `interval_ms=2000`，`timeout_ms=100`。
3. 丢弃 sequence/sender_id 不匹配、负 delay、delay 超过 `max_delay_us`、offset 单次跳变超过 50ms 的样本。
4. 保留最近 10 个有效样本。
5. offset 使用 `0.8 old + 0.2 measured` 平滑。
6. heartbeat 增加字段：

```json
{
  "clock_sync_valid": true,
  "clock_offset_us": 1234,
  "clock_delay_us": 800,
  "clock_drift_ppm": 1.2,
  "clock_last_sync_us": 1710000000000000,
  "clock_samples": 10
}
```

## receiver 行为

新增文件：

```text
02_receiver_linux/include/gwv3_receiver/clock_sync_manager.hpp
02_receiver_linux/src/clock_sync_manager.cpp
```

特性：

1. 独立线程监听 clock sync UDP 端口。
2. 只负责响应 probe，不在 receiver 侧直接计算 NTP offset，因为 receiver 没有 `t4_sender_recv_us`。
3. receiver 从 sender heartbeat/report 更新每个 `sender_id` 的 `ClockModel`。
4. `/api/status` 增加顶层 `clock_sync` 列表，并在每个 camera 项里输出当前 sender 的 clock model。
5. 模型默认 10 秒超时，超时后 `clock_sync_valid=false`，但媒体包照常接收和录制。

## global_timestamp_us

当前媒体包中：

```text
timestamp_us              相机/SDK 原始帧时间戳
system_timestamp_us       sender 本机系统时间戳
```

CLOCK_SYNC 的 offset 是 sender 系统时钟到 receiver 系统时钟的映射，因此 receiver 计算 `global_timestamp_us` 时优先使用：

```text
packet.system_timestamp_us + clock_offset_us
```

如果 `system_timestamp_us` 缺失，则退回：

```text
packet.timestamp_us + clock_offset_us
```

没有有效 clock model 时：

```text
clock_sync_valid=false
global_timestamp_us=sender 系统时间戳，缺失时为 timestamp_us
```

原始 `timestamp_us` 不会被覆盖。

## frames.csv 新增列

`frames.csv` 和录制过程中临时使用的 `rgb_recorded_frames.csv` 追加以下列：

```text
sender_id
camera_id
sender_timestamp_us
sender_system_timestamp_us
receiver_receive_timestamp_us
clock_sync_valid
sender_offset_us
sender_delay_us
sender_drift_ppm
global_timestamp_us
```

旧字段不删除，旧列顺序保持不变，新字段追加在行尾。

## 配置

sender：

```json
{
  "clock_sync": {
    "enabled": true,
    "receiver_ip": "192.168.66.196",
    "port": 50012,
    "interval_ms": 2000,
    "timeout_ms": 100,
    "max_delay_us": 100000,
    "sample_window": 10
  }
}
```

receiver：

```json
{
  "clock_sync": {
    "enabled": true,
    "bind_ip": "0.0.0.0",
    "port": 50012,
    "model_timeout_ms": 10000
  }
}
```

如果配置缺失，会使用默认值。若启用的 preview UDP 与 CLOCK_SYNC 使用同一个端口，程序会拒绝启动，避免端口冲突。

## 验证

日志中应能看到：

```text
clock_sync listening on 0.0.0.0:50012
clock_sync response sent sender_id=xxx sequence=xxx
clock_sync sender_id=xxx offset_us=xxx delay_us=xxx drift_ppm=xxx samples=xxx healthy=true
clock_sync updated sender_id=xxx offset_us=xxx delay_us=xxx drift_ppm=xxx samples=xxx valid=true
```

REST 状态：

```bash
curl http://127.0.0.1:18080/api/status
```

重点查看：

```text
clock_sync[].clock_sync_valid
clock_sync[].clock_offset_us
clock_sync[].clock_delay_us
cameras[].clock_sync_valid
```
