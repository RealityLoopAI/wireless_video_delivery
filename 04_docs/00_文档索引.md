## 2. 当前事实的判断标准

正式文档以当前分支代码、配置模板和主文档为准。

如果历史文档、现场记录和当前主文档冲突，优先级如下：

1. 当前代码和配置模板。
2. 当前主文档。
3. 组件 README。
4. 历史归档文档。

历史归档可以帮助理解为什么这么改，但不能直接当作当前实现。

## 6. 维护规则

以后更新文档时遵守这些规则：

1. README 只写项目简介、阅读入口、目录和关键边界。
2. 当前实现写进主文档，不要散落在多个历史记录里。
3. 历史问题只保留结论、根因、修复方式和验证方法。
4. 现场 IP、设备名、路径可以写；密码和私有凭据不能写。
5. 新增功能必须同时更新运行手册、接口参考或数据链路中对应位置。
6. 规划中的能力必须明确标注为后续规划，不能写成当前已实现。
