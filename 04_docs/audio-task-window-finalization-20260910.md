# 2026-09-10 任务音频结束边界与恢复片段修复

## 结论与范围

本次修复接收端任务音频的结束边界、恢复历史缺失的表达，以及收尾占用调度锁的问题。
没有修改 TCP 媒体协议、视频编码、原始时间戳、RGBD 配对、历史 NAS 文件。
本修复不等于解决无线拥塞或补回发送端已经丢弃的帧。

## 实现

1. 每个任务在本地 staging 建立匿名磁盘槽日志，记录原始编码包及该槽统计，不占用无界 Python 内存，不上传 NAS。
2. 仅在最终结束边界早于已写数据时，按槽日志重建 Opus、CSV 和统计。复用编码包，不重新压缩音频。
3. 删除窗口之外的收包、补静音、丢弃计数和播放事件；如果裁剪后根本没收到包，不保留虚假的 `audio.opus`。
4. 恢复只能回放仍在缓存内的真实历史。缓存外前缀不再伪造静音，新增 `history_unavailable_us` 和 `partial_start`，质量为 `partial`，`audio_valid=false`。
5. 重封装、哈希和文件同步不再持有音频调度锁；同目录收尾期间禁止重复创建任务。
6. 实机短测定位到 e8 的 32 个缺失槽对应 32 个迟到包。归档等待从 250 ms 调为 2,000 ms；52 的重传等待仍取较大的 8 秒，不改变实时监听或关键词识别。超过等待期限的包仍可能缺失，不能代替网络治理。

正常按时停止不需要重新封装。音频仍以 20 ms Opus 包为边界，不是逐采样裁剪；非整包结束时间允许不足 20 ms 的尾部边界差。
槽日志在任务完成后关闭删除，不是断电持久化日志，也不能恢复网络上从未收到的数据。

## 下游注意事项

- NAS 正式消费仍以 `recording_ready.json` 为准；`ready` 表示交付完成，不表示内容无缺口。
- 恢复音频的样本零点使用 `first_audio_global_us`，不要假设文件第一采样就是原录制窗口开始。
- 按实际音频时间范围合并恢复文件，重叠时间区间不能重复计算缺失秒数。
- `history_unavailable_us` 表示本次任务未能回放的历史，不等于证明麦克风静音或网络丢包。
