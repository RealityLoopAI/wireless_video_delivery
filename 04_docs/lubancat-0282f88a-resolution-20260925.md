# cam02：RGB 1280×800、深度 320×180 部署记录

2026-09-25，对发送端 `192.168.1.91`、Gemini 305 `CV275610004S` 应用用户要求的分辨率配置。接收端 `192.168.1.196` 无需修改或重启。

## 最终配置

| 项目 | 部署值 | 实际验证 |
|---|---|---|
| RGB 采集/照片 | 1280×800，30 FPS，MJPG | 原始 JPEG、相机探针和录像均为 1280×800 |
| RGB 录像 | H.264，MPP 硬件编码，2 Mbps | 1280×800、完整范围、smpte170m |
| 深度 | 320×180，30 FPS，Y16 | 探针、录像、接收端公告均为 320×180 |
| 深度传输/归档 | zlib / FFV1 gray16le | 保留 16 位深度、无损压缩 |
| 原生自动曝光 | 开启，Color 测光，最长 5 ms | 全部录像 RGB 帧 AE=1，曝光 3.9–5 ms |

320×180 是此前设备枚举中支持的最低深度尺寸。本次原生双流探针验证该组合可同时工作，稳定阶段约 30 FPS，未丢失源帧号。最低深度尺寸减少空间采样点，细小物体和边缘的深度细节相应减少；不会降低 RGB 尺寸。

旧配置写的是深度 `320×200 / Y12`，但设备不支持这一组合，实际回退为 `848×530`。这次按实际支持的 `320×180 / Y16` 设置，像素量减少约 87.2%。不能只看配置文件中的数字判断相机实际分辨率。

本次只有 RGB 尺寸和深度尺寸/格式改变；发送端二进制、MPP 补丁、Color 测光启动项、5 ms 上限和 Wi-Fi 优先级配置均保留。回退备份和哈希见部署 manifest。

## 验证范围和限制

- 本次是约两分钟的最终配置实录，不是长时或自动切片压力测试，也没有重做真实语音命令/物理按键交互；音频归档和解码已检查。
- 启动阶段曾出现一次编码输出滞后重置和短暂 TCP 背压，归档日志如实保留；稳态实录期间无源帧号缺失。这次配置变更不代表启动阶段问题已修复。
- 原始照片是相机 JPEG，分辨率提高不保证所有距离、运动和暗光都清晰；录像仍使用原有 2 Mbps。保留当前码率避免未经验证增加无线负载，未声称录像压缩细节已经最优。
- 旧的 640×480 照片不会被此配置补出高分辨率细节。新的原始 JPEG 在 `voice_photos/lubancat-0282f88a_cam02/2026-09-25/11-01-25/20260925_110125.jpg`，确认为 1280×800。

## 回退

先正常停止本相机录像并等候尾帧、收尾和归档完成，再停止发送服务，恢复备份并启动：

```sh
sudo systemctl stop gwv3-gemini-sender.service
sudo install -m 0644 /var/backups/gwv3-resolution-20260925/sender.before.json /etc/gwv3/sender.json
sudo systemctl start gwv3-gemini-sender.service
```

该备份恢复本次调整之前的 RGB 640×480 及旧深度配置，因此也会恢复旧深度回退/负载问题。若只回退深度，使用同目录的 `sender.rgb1280-before-depth-change.json` 保留 RGB 1280×800。两者均保留此前 Color 测光和 5 ms 上限。
