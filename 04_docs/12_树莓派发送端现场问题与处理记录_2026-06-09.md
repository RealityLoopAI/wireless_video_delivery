# 树莓派发送端现场问题与处理记录 2026-06-09

## 1. 现场范围

设备：

```text
发送端：Raspberry Pi
接收端：192.168.66.196
网络：5GHz Wi-Fi -> AP 模式路由器 -> 接收端有线
工程：wireless_video_delivery
```

本次记录只覆盖树莓派单发送端现场排查，不覆盖 RK3588 / 香橙派历史结论。

## 2. 问题清单

### 2.1 发送端 Wi-Fi 守护误判，子进程无法拉起

现象：

```text
watchdog 持续尝试切换固定 SSID
实际已经连上可用 Wi-Fi，但 sender 子进程不启动
```

原因：

```text
sender_watchdog.sh 硬编码了现场 Wi-Fi 名称
sender_wifi_guard.sh 依赖 iw，设备上缺少 iw 时无法正确检查链路
```

处理：

```text
05_tools/sender_watchdog.sh
05_tools/sender_wifi_guard.sh
```

修复点：

```text
默认 Wi-Fi 名称和最小频率改为环境变量可配置
Wi-Fi 链路检查增加 nmcli fallback，缺少 iw 时仍可工作
```

### 2.2 接收端存在多个媒体客户端，导致 TCP 背压

现象：

```text
sender 日志持续出现 media TCP packet dropped under backpressure
接收端 active media clients 异常偏多
RGB / Depth 实际发送速率显著低于输入帧率
```

原因：

```text
接收端同时存在多个媒体连接或旧连接未清理
接收端消费不及时，发送端 TCP 队列堆积
```

处理：

```text
清理接收端多余媒体客户端
发送端增大发送缓冲
```

发送端配置调整：

```text
transport.send_buffer_bytes: 1048576 -> 4194304
```

### 2.3 深度默认最高档位一度掉到约 6~7fps

现象：

```text
Depth 配置 1280x800@30
实际 depth_input_fps 只有约 6~7
Wait for frame timeout
```

原因：

```text
USB 线缆/链路质量不稳定
usbfs_memory_mb 默认仅 16，深度大吞吐时缓冲不足
```

处理：

```text
更换线缆后，1280x800@30 可恢复到接近 30fps
将 usbfs_memory_mb 提升到 256
```

说明：

```text
usbfs_memory_mb 的持久化需要在系统侧加入：
usbcore.usbfs_memory_mb=256
```

### 2.4 深度恢复到 1280x800@30 后，整机接近满载

现象：

```text
Pipeline source frameset queue fulled, drop the oldest frame!
RGB 帧率被明显拖低
CPU 基本无空闲
```

原因：

```text
树莓派在 RGB 1080p30 + Depth 1280x800@30 + x264 软件编码 + zlib 压缩 下接近上限
```

处理：

```text
Depth 降到 640x400@30
保留 RGB 1920x1080@30
```

### 2.5 RGB 画面偏暗，但提高曝光会拖垮帧率

现象：

```text
用户反馈 RGB 偏暗
提高 exposure 到 180 / 220 后，RGB 与 Depth 帧率明显下降
```

原因：

```text
当前整机余量有限，提高曝光后采集与处理链路更容易失稳
gain 配置写入 120，但设备实际读回始终为 80
```

处理：

```text
回退到 exposure=157
保留 gain=120 配置，但按设备实际读回 80 记录现场状态
```

结论：

```text
当前设备上，RGB 亮度不能继续靠提高 exposure 解决，否则直接影响 30fps。
```

## 3. 当前建议稳定配置

文件：

```text
06_configs/sender_raspberrypi-01_x264.json
```

当前配置要点：

```text
RGB:   1920x1080@30 MJPG -> H.264(x264enc) 6Mbps
Depth: 640x400@30 y12 -> zlib
send_buffer_bytes: 4194304
auto_exposure: false
auto_exposure_priority: 0
exposure: 157
gain: 120 (设备实际常读回 80)
```

## 4. 当前稳定性结论

在以下前提下：

```text
接收端只保留一个有效媒体客户端
5GHz 信道固定
usbfs_memory_mb = 256
当前 Depth 使用 640x400@30
```

发送端最近稳定表现为：

```text
RGB 输入约 30fps，实际发送约 29~30fps
Depth 输入约 30fps，实际发送约 29~30fps
rgb_send_failures=0
depth_send_failures=0
```

网络侧表现：

```text
Ping 192.168.66.196: 0% packet loss
RTT 通常约 2~10ms，偶发尖峰但不持续
```

## 5. 对后续设备复制的建议

1. 树莓派默认不要直接上 `1280x800@30` Depth 长时间运行。
2. 先保证 `usbfs_memory_mb=256`，再做深度高档位测试。
3. 接收端必须避免残留多个媒体客户端，否则会再次触发背压。
4. Wi-Fi 守护不要硬编码单一 SSID，现场切换网络时应通过环境变量配置。
5. 现场验收应优先看发送端 `rgb_sent_packets_s` / `depth_sent_fps` 与 `*_send_failures`，不要只看接收端显示窗口。
