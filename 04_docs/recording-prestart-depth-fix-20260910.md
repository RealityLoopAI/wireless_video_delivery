# 等待首个 RGB 关键帧时深度缺头（2026-09-10）

## 实录发现

修复 sender 编码时间戳与缓冲后，六路 300 秒验收会话为 `1789010282064717`，
NAS 相机目录时间为 `2026-09-10/111803`。该轮**整体验收失败**，没有伪装成通过。

- 六路 RGB 的源帧号均连续，无全局时间回退，全部可完整解码。
- 52d2：首个 RGB 的采集时间为 `1789010283089506`，接收时间为
  `1789010292744554`，晚到约 9.66 秒；深度文件首帧比录制窗口晚 9.652275 秒。
- e8：首个 RGB 晚到约 1.53 秒；深度文件首帧比窗口晚 1.416616 秒。
- 两个目录均 `ready=true`，但质量为 `partial`，说明“交付完成”和“录制完整”是不同概念。
- 其余四个目录质量为 `complete`；停止到六路 NAS 交付状态完成为 28.222 秒。

证据在 `08_reports/rgb-encoder-fix-20260910/recording.json`、`recording-analysis.json`。
12 个文件全帧解码均无错误，视频帧数与 CSV 相符。异常是头部缺少数据，不是封装损坏。

## 原因

`ReceiverApp::write_record_job()` 原来在 segment 尚未建立且相机预期有 RGB 时，
会直接丢弃所有深度包，直到收到可解码的首个 RGB（带 SPS/PPS 的 IDR）。
RGB 与 Depth 通过独立 TCP 通道到达；某条 RGB 通道积压时，Depth 仍然正常到达，
因此等待 RGB 的时间被错误地转换成了深度文件缺头。

隔离测试先发送 60 个深度包，延迟交付相应 RGB，旧生产二进制可确定性复现丢弃。
这项缺陷原本已经存在：`90da5c8bcb94` 与 sender 修复前的主分支 Receiver 源码相同。
本轮 sender 修复后验证范围更完整，暴露了这项接收端问题。

## 修复策略

保留“RGBD 目录等待可解码 RGB 再建立”的规则，不创建不可解码的深度独立尾片。
等待期间暂存属于当前录制窗口的深度 **压缩包与原始元数据**，不长期保留解压像素。
仍在录制 worker 上先执行现有解压与布局校验，拒绝异常包；暂存补写时再解压。
这项额外解压只发生在等首个 RGB 的阶段，正常录制路径不增加解压次数。
首个 IDR 建立 segment 后，由同一个录制 worker 补写暂存深度。

边界保护：

- 每相机最多 900 包、16MiB，且不超过原相机录制队列上限的四分之一。
- 全部相机暂存合计最多 64MiB，且不超过全局录制队列上限的四分之一。
- 暂存字节纳入原 `record_queue_total_bytes` 总预算；全局预算使用原子预留。
- 满时明确计入 `segment_prestart_depth_drops`，不无限增长、不假装完整。
- 新会话、关闭 segment 或写入错误时清理未能补写的暂存，避免串入下一次录制。
- 补写时按 segment 时间窗口过滤；未来切片的数据不塞进当前切片。
- 原始时间戳、帧号、身份、正式 NAS 就绪契约及旧 CSV 字段保持不变。

新增状态：`record_prestart_depth_total_bytes`（全局），以及每相机的
`record_prestart_depth_bytes`、`record_prestart_depth_packets`、
`record_prestart_depth_replay_attempts`。最后一项表示补写尝试，不冒充写入成功计数。
暂存、尝试补写和实际丢弃分别统计。

## 测试与限制

新测试 `test_receiver_prestart_depth.py` 覆盖延迟 RGB 后完整补写、容量上限、
无 RGB 时不创建目录、停止后释放预算、重启录制不混入旧会话。
原有空闲恢复测试仍要求不能产生深度独立尾片，只将“正在等待”从丢弃改为暂存。
本机缺少 `ffmpeg`，其文件集成测试不能在本机完成；使用接收端独立端口与临时目录原生验证。

暂存只能修复“已经收到但原来错误丢弃”的数据。无线链路永久丢失、
相机没有采集到、超过有限预算或始终没有可解码 RGB 时，不能保证完整。
第一轮 52d2 还有 212 条 RGB 的 `clock_sync_valid=false`；保留该标记，
不能把数据完整恢复等同于这些帧已经通过跨设备时间校准。
音频出现 UDP 间断及 SDK 标定参数查询警告，也未被本轮视频缓冲修改修复。

接收端 x86_64 原生 34/34 项 CTest 已通过，包含新增暂存、恶意压缩布局拒绝、
时间模型历史、停止尾帧排空、连接隔离、staging/NAS、上传故障注入等测试。
首轮回归的两个失败也保留在报告中：测试未等 ready 发布，以及暂存过早延后了坏包拒绝。
已分别修正测试等待条件、将暂存移至现有解压校验之后，没有删掉失败断言绕过问题。
后续上线及再次录制结果在验收完成后补充。
