# 发送端稳定性与内存拷贝优化

日期：2026-06-17

## 背景

本次优化针对发送端审查发现的几个根因级风险：

1. 主 RGB H.264 在发送队列覆盖 P 帧后，接收端可能继续收到后续 P 帧，导致解码卡顿、花屏或预览不动。
2. 主 RGB、Depth、Web RGB preview 共用一个发送队列和 TCP 连接，网页预览在网络或接收端背压时会挤占主录制流。
3. `web_rgb_preview.fps` 以前只出现在配置和状态里，发送端实际仍按源 RGB 帧率编码预览。
4. 发包时会把 header 和 payload 拼成一整块 `std::vector<uint8_t>`，主 RGB/Depth/Web preview 都多一次大块内存拷贝。
5. zlib depth 压缩在采集线程内执行，压缩耗时会拖慢下一次 `waitForFrames()`。
6. MJPEG 校验使用 libjpeg `setjmp/longjmp`，存在跨 C++ 对象析构路径的风险。
7. 发送端 stdout 日志长期追加，缺少轮转。

## 主要改动

### 1. 主 RGB 队列覆盖保护

`LatestMediaQueue` 现在返回明确的发布结果：

- `queued`
- `overwritten`
- `rejected_occupied`
- `rejected_stopping`

主 RGB 非关键帧如果会覆盖尚未发送的旧包，会被拒绝入队，并触发关键帧保护。后续非 IDR 帧会被丢弃，直到下一个 IDR 到来。这样可以避免接收端收到缺失参考帧后的 H.264 P 帧链。

如果覆盖发生时新包本身是 IDR，则允许发送，不额外等待下一个 IDR。

### 2. 发送优先级

媒体发送线程现在按以下优先级取包：

1. 主 RGB
2. Depth
3. Web RGB preview

网页预览仍然可用，但在背压场景下优先让主录制流和深度流通过。

### 3. Web RGB preview 真正限流

新增每路相机的 `next_web_rgb_preview` 节流点。`web_rgb_preview.fps` 现在真正控制发送端预览编码频率，不再每个源 RGB 帧都生成网页预览包。

### 4. Header/Payload 分开发送

公共协议新增 `build_media_header()`。发送端媒体 job 现在保存：

- header vector
- owned payload vector，或外部 payload 指针加生命周期 owner

TCP 发送层新增 `MediaPacketView`，用 `sendmsg()` 发送 header 和 payload 两段数据，避免发包前再把 payload 拷贝进一整个 packet vector。

说明：这不是完整硬件零拷贝。GStreamer 编码输入/输出和部分 OpenCV 转换仍然存在拷贝，但主发包路径已经减少一次大块 payload 拷贝。

### 5. Depth zlib 异步压缩

zlib depth 不再在采集线程中压缩。采集线程只把最新 raw depth 放入 `LatestDepthCompressionQueue`，压缩线程异步压缩后再发布到媒体发送队列。

压缩队列同样是 latest-slot 语义，压缩跟不上时丢旧 depth，避免积压拖垮采集。

未压缩 depth 不再拷贝进整包，而是用 SDK depth frame 的 shared owner 保住 payload 生命周期。

### 6. MJPEG 校验安全化

MJPEG 校验仍使用 libjpeg，但 row buffer 改为 C buffer，并在 `longjmp` 错误路径显式释放，避免 `longjmp` 跨过 `std::vector` 析构。

### 7. 配置校验收紧

新增启动前校验：

- `rgb_profile/depth_profile` 的 `width/height/fps` 不能为负数。
- `rgb_encoding.mode` 当前只允许 `hardware`。
- `rgb_encoding.gstreamer_encoder` 不能为空。
- `rgb_encoding.bitrate_bps` 必须为正数。

现有仓库内发送端配置均已通过校验。

### 8. 发送端日志轮转

新增：

- `05_tools/rotate_sender_logs.sh`

并接入：

- `05_tools/start_sender.sh`
- `05_tools/start_sender_preview.sh`
- `05_tools/sender_watchdog.sh`

默认超过 256MB 后归档压缩，归档保留 30 天。可通过环境变量调整：

- `GWV3_MAX_LOG_BYTES`
- `GWV3_MAX_ARCHIVE_DAYS`

## 注意事项

本次没有自动重启现场发送端。构建验证时发现本机已有发送端和多个 watchdog 进程在运行，避免直接抢占相机或中断现场流。

如需让正在运行的本机发送端应用新代码，需要在合适时机停止旧 watchdog/child 后重新启动发送端。
