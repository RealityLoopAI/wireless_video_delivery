# 2026-06-05 发送端最高深度档网络与设备压力实测

## 1. 测试目的

确认现场 `SV1301S_U3 / AY2MC31010W` 在单路最高 Depth profile 下，发送端、USB、Depth zlib、Wi-Fi 和接收端链路是否能维持 30fps。

## 2. 测试配置

```text
sender: orangepi5pro-66-133 / RK3588 / Orange Pi 5 Pro
receiver: 192.168.66.196
config: 06_configs/sender_rk3588-01_cam02_depth_max.json
camera_id: cam02
RGB: 1920x1080@30 MJPG -> H.264/mpph264enc 12Mbps
Depth: 1280x800@30 y12 -> uint16 depth frame -> zlib
Depth uncompressed size: 1280 * 800 * 2 = 2048000 bytes/frame
Preview: enabled
Wi-Fi: 土著拯救器-5G, 5220MHz
```

启动命令：

```bash
./12_build/bin/gemini_sender --config 06_configs/sender_rk3588-01_cam02_depth_max.json
```

## 4. 结论

1. 单路最高 Depth 档在当前良好 Wi-Fi/接收端状态下可以跑满约 30fps，RGB 和 Depth 发送失败均为 0。
2. 该配置网络总码率约 74.5Mbps，其中 Depth zlib 后约 62.5Mbps；Depth 是主要网络和 CPU 压力来源。
3. Depth USB 输入约 492Mbps，已经显著高于默认 `640x400@30 y12`；需要确认相机走 USB3，不应把相机挂在共享 USB2 hub 上交付最高档。
4. 默认双路稳定配置仍保持 `Depth 640x400@30 y12 -> zlib`。`sender_rk3588-01_cam02_depth_max.json` 只作为单路容量和画质验证配置。
5. 如果 `ss -tinpe 'dst 192.168.66.196:50010'` 的 Send-Q 长期接近 4MiB，或者 `rgb_send_failures` / `depth_send_failures` 非 0，应认为端到端吞吐不足，切回默认稳定档或降低 Depth 帧率。

## 5. 当前硬件状态

测试结束后相机已从 USB 断开。`lsusb` 不再显示：

```text
2bc5:0614 ORBBEC Depth Sensor
2bc5:0511 USB 2.0 Camera
```

发送端 watchdog 仍在运行并周期重启子进程，日志表现为：

```text
camera unavailable at startup camera_id=cam02 error=no Orbbec device found
camera reconnect failed camera_id=cam02 ... error=no Orbbec device found
```

这是硬件不在线状态，不是媒体发送链路在最高 Depth 档下失败。重新插上相机后，watchdog 会继续尝试拉起发送端。
