# 2026-05-29 RGB/Depth 对齐标定缺失与发送端配置说明

## 结论

下游工程师反馈的 `calibration.available is false; cannot align depth to RGB` 是正确结果，不是离线对齐脚本故障。

该 segment：

```text
\\REALITYLOOP\video_database\orangepi5pro-66-133_cam02\2026-05-29\161221
```

对应本机路径：

```text
/home/fz/Desktop/nas/orangepi5pro-66-133_cam02/2026-05-29/161221
```

录制时没有收到可用的 `camera_announce` 标定，`align_auto_test_calibration.json` 中 `rgb_profile`、`depth_profile` 和 `calibration.data` 均为空，因此不能做 Depth -> RGB 几何投影。

## 现场事实

失败命令：

```bash
python 05_tools\align_depth_to_rgb.py "\\REALITYLOOP\video_database\orangepi5pro-66-133_cam02\2026-05-29\161221"
```

脚本返回：

```text
error: calibration.available is false; cannot align depth to RGB
```

该段标定文件关键内容：

```json
{
  "rgb_profile": {},
  "depth_profile": {},
  "calibration": {
    "available": false,
    "source": "missing_camera_announce",
    "data": {}
  },
  "camera_announce_raw": ""
}
```

该段媒体文件本身存在：

```text
RGB   1920x1080 H.264
Depth 640x400   FFV1 gray16le
```

但只有视频和 depth 像素不够。离线几何对齐必须依赖以下标定字段：

```text
calibration.data.depth_intrinsic
calibration.data.rgb_intrinsic
calibration.data.depth_distortion
calibration.data.rgb_distortion
calibration.data.d2c_transform
```

缺少这些字段时，脚本拒绝生成对齐结果是正确保护，避免输出伪对齐数据。

## 根因

本次问题有两层原因：

1. `161221` 录制当时接收端没有拿到该路相机的 live `camera_announce`，所以 segment 内没有任何可用标定。
2. 当前发送端运行的高画质 profile 是 `RGB 1920x1080 + Depth 640x400`。Orbbec SDK 对这组 profile 返回的 RGB 内参为 0，当前接收端状态也显示 `calibration_available=false`。

当前缓存 announce 中可见：

```text
rgb_profile = 1920x1080
depth_profile = 640x400
rgb_intrinsic = fx=0, fy=0, cx=0, cy=0, width=0, height=0
calibration.warning = incomplete_calibration
```

同一相机的 raw calibration list 中存在可用候选：

```text
RGB   640x480
Depth 640x400
Depth -> RGB transform 非零
```

因此目前可验证的对齐采集组合应使用 `RGB 640x480 + Depth 640x400`。

## 需要改哪里

接收端和 `05_tools/align_depth_to_rgb.py` 不需要改。脚本拒绝缺标定数据是正确行为。

需要改发送端配置。当前发送端默认脚本使用：

```text
05_tools/start_sender.sh
05_tools/start_sender_preview.sh
```

默认配置为：

```text
06_configs/sender_rk3588-01_two_cameras.json
```

该配置当前是高画质方案：

```json
"rgb_profile": {
  "width": 1920,
  "height": 1080,
  "fps": 30,
  "format": "mjpg"
}
```

如本次录制目标是 RGB/Depth 对齐，应改为或新增一个对齐专用配置：

```json
"rgb_profile": {
  "width": 640,
  "height": 480,
  "fps": 30,
  "format": "mjpg"
},
"depth_profile": {
  "width": 640,
  "height": 400,
  "fps": 30,
  "format": "y12"
}
```

建议不要直接覆盖高画质配置，而是按需复制基础配置另存为本地对齐采集配置。当前仓库不再维护固定的对齐专用配置文件名，避免把临时现场配置误当成通用交付配置。

```text
cp 06_configs/sender_rk3588-01_two_cameras.json /tmp/sender_two_cameras_align.json
```

修改本地配置后，启动时显式指定：

```bash
./05_tools/start_sender.sh /tmp/sender_two_cameras_align.json
```

## 录制前检查

录制前必须确认接收端状态中目标相机满足：

```text
live = true
announce_live = true
calibration_available = true
announce_rgb_width = 640
announce_rgb_height = 480
announce_depth_width = 640
announce_depth_height = 400
```

可以通过 Web 页面查看，也可以请求：

```bash
curl http://127.0.0.1:18080/api/status
```

如果 `calibration_available=false`，这次录制不要交给下游做 RGB/Depth 几何对齐。

## 对下游交付建议

对 `161221` 这段数据：

```text
不建议作为 RGB/Depth 对齐样例。
不建议手工把历史标定硬塞到该 segment。
不建议用 640x480 标定直接解释 1920x1080 RGB，除非后续通过实拍标定板验证 FOV、裁剪和缩放关系完全一致。
```

后续应重新录制一段 `RGB 640x480 + Depth 640x400`，且录制前确认 `calibration_available=true`。录制完成后再运行：

```bash
05_tools/run_align_depth_to_rgb.sh <segment_dir>
```

输出：

```text
depth_aligned_to_rgb.mkv
depth_aligned_to_rgb.json
```

## 当前系统边界

当前系统不会在录制结束后自动生成 aligned depth。对齐是手动离线步骤。

`calibration.available=false` 时，离线脚本必须失败；这是数据质量保护，不应绕过。
