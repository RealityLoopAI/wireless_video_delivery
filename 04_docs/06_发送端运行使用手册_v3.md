# 发送端运行使用手册 v3

## 1. 适用范围

本文档说明 Orange Pi 5 Pro 发送端工程的构建、配置、启动、验证和常见问题。GitHub 仓库以源码形态交付，不包含当前机器的运行日志、PID 文件和压缩归档包。

发送端主体目录：

```text
01_sender_linux/     发送端 C++ 源码
03_common_core/      媒体包协议公共定义
04_docs/             文档
05_tools/            一键启动、停止、状态脚本
06_configs/          发送端配置
11_third_party/      Orbbec SDK 放置说明
```

## 2. 当前默认运行规格

```text
设备: Orange Pi 5 Pro / RK3588S / aarch64
相机: Orbbec SV1301S_U3
sender_id: orangepi5pro-01
camera_id: cam01
receiver_ip: 192.168.1.107
media_port: TCP 50010
status_port: UDP 50011
RGB: 1920x1080@30 MJPG -> H.264 12Mbps
Depth: 640x400@30 raw depth -> zlib
```

默认配置文件：

```text
06_configs/sender_orangepi5pro-01_depth_zlib.json
```

兼容 raw Depth 配置：

```text
06_configs/sender_orangepi5pro-01.json
```

兼容配置保留 `Depth compression = none`，用于未升级 zlib 解压能力的接收端。

## 6. 配置

修改接收端 IP：

```json
"receiver": {
  "ip": "192.168.1.107",
  "media_port": 50010,
  "status_port": 50011
}
```

修改 RGB 规格和码率：

```json
"rgb_profile": {
  "width": 1920,
  "height": 1080,
  "fps": 30,
  "format": "mjpg"
},
"rgb_encoding": {
  "codec": "h264",
  "mode": "hardware",
  "gstreamer_encoder": "mpph264enc",
  "bitrate_bps": 12000000
}
```

修改 Depth 压缩：

```json
"depth_transport": {
  "compression": "zlib"
}
```

支持值：

```text
none
zlib
```

使用 `zlib` 时，接收端必须先解压 Depth payload，再按 `uint16 little-endian` 解析。

## 7. 一键运行

后台启动，不打开本地预览：

```bash
./05_tools/start_sender.sh
```

带本地 RGB + Depth 预览启动：

```bash
./05_tools/start_sender_preview.sh
```

指定其他配置启动：

```bash
./05_tools/start_sender.sh 06_configs/sender_orangepi5pro-01.json
```

查看状态：

```bash
./05_tools/status_sender.sh
```

停止：

```bash
./05_tools/stop_sender.sh
```

日志：

```text
08_reports/sender_logs/sender.log
08_reports/sender_logs/sender_stdout.log
```

## 8. 验证

配置校验：

```bash
./12_build/bin/gemini_sender --config 06_configs/sender_orangepi5pro-01_depth_zlib.json --validate-config
```

本机采集验证，不发送、不预览：

```bash
./12_build/bin/gemini_sender --config 06_configs/sender_orangepi5pro-01_depth_zlib.json --run-seconds 5 --no-preview --no-send
```

确认实际走无线还是有线：

```bash
ip route get 192.168.1.107
ss -tinpe 'dst 192.168.1.107:50010'
iw dev wlan0 link
```

正常无线发送示例：

```text
192.168.1.107 dev wlan0 src 192.168.1.109
ESTAB 0 0 192.168.1.109:xxxxx 192.168.1.107:50010
```

确认相机实际 profile：

```bash
tail -n 80 08_reports/sender_logs/sender_stdout.log
```

应能看到类似：

```text
camera started camera_id=cam01 color=1920x1080@30 format=mjpg depth=640x400@30 format=unknown
```

## 9. 常见问题

接收端只收到 H.264 头，没有有效画面：

```text
确认发送端源码包含 videoconvert 后强制 NV12 的修复。
确认运行的是最新构建出的 gemini_sender。
```

接收端无法解析 Depth：

```text
确认接收端已支持 codec_or_compression=zlib。
未升级接收端时改用 sender_orangepi5pro-01.json。
```

从有线切到无线后连接异常：

```text
先执行 ./05_tools/stop_sender.sh
再执行 ./05_tools/start_sender.sh
```

原因是已有 TCP 连接会保留旧本地 IP，需要重启 sender 重新建连。

本地没有预览窗口：

```text
使用 ./05_tools/start_sender_preview.sh。
确认 DISPLAY 正确。
无桌面环境时使用 ./05_tools/start_sender.sh。
```

Wi-Fi 多路卡顿：

```text
单路 1080p RGBD 当前实测约 15-20Mbps。
6 路建议按 150-210Mbps 工程预算规划，并给 Wi-Fi 留 300-500Mbps 稳定可用吞吐。
接收端 NAS 建议有线接路由器/交换机。
多路建议使用 2 个 Wi-Fi 6/6E AP，每个 AP 承载 3 路。
```
