# 六路无线抖动与接收端收包调优

日期：2026-09-01

## 1. 问题表现

六路发送端逐步上线后出现以下现象：

1. 个别 LubanCat 相机采集仍为 30 FPS，但 RGB 发送降到 1 到 4 FPS。
2. 接收端媒体年龄偶发达到数秒，sender 出现 `rgb queue overwrite` 或 `rgb encoder output lag reset`。
3. 强 Wi-Fi 信号下，LubanCat 到接收端的 ping 仍达到 290 到 800 ms。
4. 接收端网卡持续出现少量 RX drop，多路同时接入时 TCP 重传明显增加。

## 2. 根因

### 2.1 接收端调优配置没有部署

仓库已有接收端 sysctl 模板，但现场仍使用：

```text
net.core.netdev_max_backlog=1000
net.core.rmem_max=4194304
RPS disabled
```

接收端是单 RX 队列 virtio 网卡，突发媒体包集中由单 CPU 处理，队列余量不足。

### 2.2 LubanCat USB Wi-Fi 驱动内部排队

三台 LubanCat 使用 `rtw_8821cu` 驱动。该 RK3576 内核没有编译 `fq`、`fq_codel` 或 `tbf`，无线接口默认是 `qdisc noqueue`，持续 TCP 上行会直接进入厂商驱动内部队列。

现场验证内核内置 `pfifo`，将根队列限制为 128 包后：

- `lubancat-4df661d7` 平均延迟从约 320 ms 降到 3.75 ms。
- `lubancat-e8cc0cb3` 在旧 AP 上第一次验证从约 290 ms 降到 7.5 ms。
- 测试期间 qdisc 无丢包，RGB/Depth 保持约 30 FPS。

### 2.3 `lubancat-52d2ef0c` 错连 2.4GHz

该设备虽然连接名是 `666666`，实际连接到 2.4GHz BSSID，协商发送速率只有 19.5 Mbps，媒体 TCP Send-Q 一度达到约 13 MB。将连接固定到 5GHz BSSID 后：

- 信号约 -27 dBm。
- 协商发送速率恢复到约 433 Mbps。
- 平均延迟降到 3.21 ms。
- TCP Send-Q 基本清空。

### 2.4 AP 负载分配

最终按实际码率而不是设备数量分配：

```text
新 5GHz AP：rk3588-ubuntu、orangepi5pro-ab748372、lubancat-e8cc0cb3
旧 5GHz AP：orangepi5pro-f022c4、lubancat-4df661d7、lubancat-52d2ef0c
```

实测约为新 AP 43 Mbps、旧 AP 33 Mbps。

## 3. 实现改动

接收端新增：

- `05_tools/apply_receiver_network_tuning.sh`
- `05_tools/install_receiver_network_tuning.sh`
- `06_configs/gwv3-receiver-network-tuning.service`

接收端持久化参数：

```text
net.core.netdev_max_backlog=16384
net.core.netdev_budget=600
net.core.netdev_budget_usecs=8000
net.core.rps_sock_flow_entries=32768
net.core.rmem_max=33554432
net.core.wmem_max=33554432
ens3 rx-0 rps_cpus=1e
ens3 rx-0 rps_flow_cnt=32768
```

LubanCat 新增：

- `05_tools/apply_sender_wifi_tuning.sh`
- `05_tools/install_sender_wifi_tuning.sh`
- `06_configs/gwv3-sender-wifi-tuning.service`

该脚本只对驱动名为 `rtw_8821cu` 的设备应用 `pfifo limit 128`，不会改变其他发送端 qdisc。

## 4. 验证结果

### 4.1 七路等效压力

在四路媒体基础上，从新旧 AP 各注入 35 Mbps TCP，接收端平均入站达到 131.82 Mbps：

- 新 AP 测试流 60 秒为 35 Mbps，TCP 重传 0。
- 非 LubanCat 三路媒体保持约 30 FPS。
- 测试同时暴露了旧 AP 上 LubanCat 的 2.4GHz 误连和驱动排队问题。

### 4.2 修复后六路稳态

最终 30 秒联合验证：

- 六路 RGB/Depth 均约 30 FPS。
- 媒体年龄为 0 到 19 ms。
- 新增 sender 丢帧为 0。
- 新增发送失败为 0。
- 接收端录制队列为 0。
- TCP 重传为 3。

接收端 virtio 网卡的累计 `rx_dropped` 仍会少量增长，但修复后没有转化为 sender 丢帧、发送失败或录制积压。进一步消除该计数需要调整虚拟机宿主侧 vNIC 队列或增加多队列，不属于当前用户态部署范围。

## 5. 部署命令

接收端：

```bash
sudo ./05_tools/install_receiver_network_tuning.sh
```

使用 `rtw_8821cu` 的 LubanCat：

```bash
sudo ./05_tools/install_sender_wifi_tuning.sh
```

安装均为开机持久化，不需要修改媒体协议、编码参数或相机档位。
