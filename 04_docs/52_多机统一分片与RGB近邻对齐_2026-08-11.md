# 多机统一分片与 RGB 近邻对齐

## 1. 问题

旧实现虽然为 `start-all` 生成统一 `recording_window_start_global_us`，但每路 `SegmentWriter` 使用自己的单调时钟计算 15 分钟轮转，并在各自下一次 IDR 到来时开新文件。其后果是：

1. 同一会话首段的逻辑起点一致，文件实际首帧仍受各相机采集相位影响。
2. 后续分片开头受各编码器 GOP/IDR 时机影响，可相差数百毫秒。
3. 一路掉线重连后会重新启动独立的 15 分钟周期。
4. 按文件序号或同一行号配对会放大误差。

这不是 CLOCK_SYNC offset 本身能解决的问题。无硬件触发时，各相机曝光相位仍然独立。

## 2. 当前实现

接收端以会话全局起点建立固定时间窗：

```text
global_segment_index = floor((global_timestamp_us - recording_window_start_global_us) / segment_duration_us)
segment_start = recording_window_start_global_us + global_segment_index * segment_duration_us
segment_end = segment_start + segment_duration_us
```

实现规则：

1. 自动轮转由媒体帧的 `global_timestamp_us` 跨越统一边界触发，不再由 writer 启动后的独立计时器触发。
2. receiver 默认在边界前 `segment_keyframe_lead_ms=500` 发送带 `target_global_us` 的关键帧预约。
3. sender 根据 CLOCK_SYNC 的 `receiver_clock - sender_clock` offset 换算目标本机时间，在第一张达到目标时间的采集帧编码前请求 IDR。
4. sender 时钟模型暂不可用时按 chrony 后的本机系统时间降级；采集时间异常时最多晚 100 ms 使用墙钟兜底，不阻塞媒体线程。
5. 相机重连时根据第一帧全局时间重新加入当前逻辑分片；同一相机同一分片的续录目录使用后缀区分。
6. 普通预览、网络恢复等即时关键帧请求保持即时行为。

## 3. 新增数据字段

`frames.csv`、`meta.json`、`recording_staged.json`、`recording_ready.json` 和状态接口增加：

```text
global_segment_index
segment_window_start_global_us
segment_window_end_global_us
segment_window_valid
```

旧字段未删除。`segment_window_valid` 按 `[start, end)` 判断。下游先筛选：

```text
stream_type == rgb
rgb_recorded == 1
recording_window_valid == 1
segment_window_valid == 1
```

## 4. 下游对齐

同一 `recording_session_id + global_segment_index` 只保证文件属于同一逻辑时间窗，不代表不同相机内容硬同步。正式配对仍按 `global_timestamp_us` 做单调、不可重复使用旧帧的近邻匹配：

```bash
python3 05_tools/build_rgb_sync_manifest.py \
  --output rgb_sync_manifest.csv \
  --max-delta-ms 33.333 \
  reference=/data/camera_a \
  camera_b=/data/camera_b \
  camera_c=/data/camera_c
```

如通过闪光灯、秒表或运动事件标定出内容固定偏移：

```bash
python3 05_tools/build_rgb_sync_manifest.py \
  --output rgb_sync_manifest.csv \
  --content-offset-us camera_b=-12000 \
  reference=/data/camera_a camera_b=/data/camera_b
```

偏移仅写入生成的 manifest，不覆盖原始 `global_timestamp_us`。建议目标阈值 20 ms，硬阈值不超过一帧 `33.333 ms`。

## 5. 能力边界

本次改动可以消除每路独立分片计时和 GOP 随机等待造成的额外误差，也能让重连设备回到统一分片时间轴。它不能让没有同步线的 Gemini 相机同时曝光。要获得画面内容级硬同步，仍需要支持硬件同步的相机、同步线和统一触发源。

## 6. 验证

已通过：

1. sender 和 receiver C++17 构建。
2. 预约时间换算、边界等待和超时兜底单元测试。
3. 三路异步切片 receiver 集成测试。
4. `frames.csv` 分片字段、统一窗口和有效行测试。
5. 单调近邻 manifest 工具测试。
6. recording uploader 故障注入与并发测试。

六路实机最终短测结果：

1. 六路共享同一个 `global_segment_index=0` 和完全相同的分片窗口。
2. 所有 MP4 可读取，均为 30 FPS；1920x1080 五路和 1280x800 一路保持原档位。
3. 所有实际录入 RGB 均满足 `segment_window_valid=1`，时间戳严格单调。
4. 六路物理首帧相对统一起点为 `1.148--58.131 ms`，跨路离散 `48.102 ms`；旧实现样本为约 `905 ms`。
5. 六路近邻清单生成 497 组，最大路间误差统计：mean `15.662 ms`、p95 `18.921 ms`、p99 `31.543 ms`、max `33.010 ms`。

物理首帧离散已经消除了预滚和随机等待下一 GOP 的主要误差，但仍超过 CLOCK_SYNC 的网络时钟误差。这部分来自独立相机的采集相位和编码器关键帧响应，不能当作硬同步；下游近邻匹配仍是必需步骤。
