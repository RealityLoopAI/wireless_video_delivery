# Orbbec 软件自适应曝光（Gemini 305）

日期：2026-08-04

## 1. 目标与范围

本功能解决 Gemini 305 原生自动曝光在场景切换时容易突然过曝，而固定手动曝光又需要人工反复调整的问题。

当前只在 `orangepi5pro-d12a4719/cam01`（192.168.66.133）的 Gemini 305 正式配置中启用。其他型号和其他发送端默认不受影响；本机 `rk3588-ubuntu/cam01` 已恢复固定手动曝光 `312/0`。方案保持 Orbbec SDK、RGB/Depth 配对、H.264 编码和媒体传输主路径不变。

## 2. 实机边界

测试档位为 RGB `1280x800@30 MJPG`、Depth `320x200@30`。

| 项目 | 实测结论 |
| --- | --- |
| 曝光 `80..325` | RGB 和 Depth 均可维持约 30fps |
| 曝光 `326..330` | 两路实际帧率下降到约 20fps |
| SDK `ACTUAL_FRAME_RATE` 元数据 | 在掉到 20fps 时仍可能错误报告 30，不可单独作为帧率依据 |
| gain `16..80` | 不直接降低帧率，但 40 以上已经明显增加高光与灰雾，48 以上纸面细节损失明显 |
| 原生自动曝光 | 静态场景可稳定在 exposure 157 / gain 16，问题主要出现在场景变化响应和测光策略 |
| AE ROI / AE max gain | 当前固件无法形成可靠限制，不作为正式控制手段 |

正式自适应范围使用 exposure `20..300`、gain `0..32`。曝光上限与实测 30fps 临界值 326 保留余量；控制器优先调整 exposure，只有曝光达到上限后才增加 gain，以减少噪点和灰雾。

## 3. 测光与控制

稳定状态下每 100ms 从相机原始 MJPEG 帧无输入复制地解码一张约 `160x100` 灰度缩略图，只统计中央 80% 区域。每次写入 SDK 曝光或增益后等待 200ms 再闭环，避免尚未反映新参数的旧帧造成连续追写。正式编码仍直接消费原始 MJPEG，不新增逐帧 BGR 转换。

当前目标为：

- P50 主体亮度目标 150，死区正负 8。
- P95 上限目标 225；P99 和高光像素比例用于保护白纸、屏幕等亮部。
- 高光阈值 245，允许比例 0.25%。
- 亮场立即处理，先降 gain，再降 exposure；暗场单次确认后即可增加 exposure。
- 普通明暗变化根据 `目标亮度 / 当前亮度` 估算目标 exposure，再以每次最多 16 的固定斜率逼近；目标附近允许更小步长。曝光到顶后的普通 gain 变化固定为对称的正负 2，严重高光仍会快速清除 gain 并以 24 回压 exposure。
- 所有输出严格限制在 exposure `20..300` 和 gain `0..32`。

P50 负责主体观感，P95/P99 负责高光保护，避免此前只看 P95 时“白纸正确但主体过暗”的问题。100ms 快速检测、200ms 写入稳定期和受限亮度比控制让大误差按近似固定斜率变化、小误差直接靠近目标，死区用于抑制稳定后的来回振荡。

## 4. 可靠性

- 配置默认关闭，只有显式启用的相机参与。
- 仅显式启用且识别到已验证 Orbbec 型号时创建控制器；当前正式配置只启用 Gemini 305。
- SDK 写入后进行属性回读；不一致视为失败，不提交控制状态。
- Gemini 305 启动后先完成 V4L2 手动模式校验，再通过 SDK 强制重下发并回读 RGB 控制，避免流启动后 gain 从配置 0 回到固件默认 16。
- 测光解码或属性写入失败只记录诊断并保持上一次手动值，不影响采集、编码、发送和重连。
- 重连后从配置基线 exposure 130 / gain 0 重新初始化，再恢复闭环。

## 5. 可观测字段

heartbeat 和发送端性能日志提供：

```text
adaptive_exposure_enabled
adaptive_exposure_luma_p50
adaptive_exposure_luma_p95
adaptive_exposure_luma_p99
adaptive_exposure_highlight_fraction
adaptive_exposure_requested_exposure
adaptive_exposure_requested_gain
adaptive_exposure_samples
adaptive_exposure_adjustments
adaptive_exposure_failures
adaptive_exposure_last_reason
```

判断 30fps 必须同时查看 `rgb_measured_fps` 和 `depth_measured_fps`，不要只看相机 SDK 元数据。

## 6. 测试

自动测试覆盖稳定死区、普通亮场、严重高光、暗场滞回、曝光优先增亮、曝光到顶后增益补偿、P50/P95 联合约束、误差比例响应和上下限保护。配置测试覆盖原生 AE 冲突、不安全曝光上限和重叠亮度目标。部署后的实机收敛与持续帧率结果记录在 `08_reports/2026-08-04_Gemini305软件自适应曝光实机验证.md`。

## 7. SV1301S_U3 参数

本机 `SV1301S_U3 / RD3013 / SDK 1.10.27` 的 SDK 属性范围为 exposure `1..5000`、gain `0..100`。但属性可写范围不等于 30fps 安全范围。`1920x1080@30 MJPG + 320x200@30 Y12` 实测 exposure 300、312、325、333、334 可维持约 30fps，350 时 RGB 已下降到约 27fps。

该型号的控制器支持和 30fps 安全边界仍保留在代码中，但按本次现场范围调整，正式配置没有启用闭环，继续使用 exposure `312`、gain `0`。此前的软件闭环试验参数和结果仅保留在历史实机报告中，不代表当前运行配置。
