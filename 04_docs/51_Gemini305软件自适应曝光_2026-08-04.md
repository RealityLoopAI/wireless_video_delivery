# Gemini 305 软件自适应曝光

日期：2026-08-04

## 1. 目标与范围

本功能解决 Gemini 305 原生自动曝光在场景切换时容易突然过曝，而固定手动曝光又需要人工反复调整的问题。

当前只在 `orangepi5pro-d12a4719/cam01` 的正式配置中启用。其他型号和其他发送端默认不受影响。方案保持 Orbbec SDK、RGB/Depth 配对、H.264 编码和媒体传输主路径不变。

## 2. 实机边界

测试档位为 RGB `1280x800@30 MJPG`、Depth `320x200@30`。

| 项目 | 实测结论 |
| --- | --- |
| 曝光 `80..325` | RGB 和 Depth 均可维持约 30fps |
| 曝光 `326..330` | 两路实际帧率下降到约 20fps |
| SDK `ACTUAL_FRAME_RATE` 元数据 | 在掉到 20fps 时仍可能错误报告 30，不可单独作为帧率依据 |
| gain `16..80` | 不直接降低帧率，但 40 以上已经明显增加高光与灰雾，48 以上纸面细节损失明显 |
| 原生自动曝光 | 静态场景可稳定在 exposure 157 / gain 16，问题主要出现在场景变化响应和测光策略 |
| AE ROI / AE max gain | 当前固件无法形成可靠限制，不作为正式控制手段 |

正式自适应范围使用 exposure `80..200`、gain `16..32`。曝光上限保留了距离 30fps 临界值 326 的余量，也限制了运动模糊和不同相机曝光时刻偏差。

## 3. 测光与控制

每 500ms 从相机原始 MJPEG 帧无输入复制地解码一张约 `160x100` 灰度缩略图，只统计中央 80% 区域。正式编码仍直接消费原始 MJPEG，不新增逐帧 BGR 转换。

当前目标为：

- P95 亮度目标 200，死区正负 8。
- 高光阈值 245，允许比例 0.25%。
- 亮场立即处理，先降 gain，再降 exposure。
- 暗场连续 3 次测光后才处理，先缓慢增加 exposure，到上限后再增加 gain。
- 所有输出严格限制在 exposure `80..200` 和 gain `16..32`。

该策略是“快速压高光、缓慢补暗部”，避免原生自动曝光的大幅跳变和软件控制来回振荡。

## 4. 可靠性

- 配置默认关闭，只有显式启用的相机参与。
- 仅识别到 Gemini 305 实机型号时创建控制器。
- SDK 写入后进行属性回读；不一致视为失败，不提交控制状态。
- 测光解码或属性写入失败只记录诊断并保持上一次手动值，不影响采集、编码、发送和重连。
- 重连后从配置基线 exposure 130 / gain 16 重新初始化，再恢复闭环。

## 5. 可观测字段

heartbeat 和发送端性能日志提供：

```text
adaptive_exposure_enabled
adaptive_exposure_luma_p50
adaptive_exposure_luma_p95
adaptive_exposure_luma_p99
adaptive_exposure_highlight_fraction
adaptive_exposure_requested_exposure
adaptive_exposure_requested_gain
adaptive_exposure_samples
adaptive_exposure_adjustments
adaptive_exposure_failures
adaptive_exposure_last_reason
```

判断 30fps 必须同时查看 `rgb_measured_fps` 和 `depth_measured_fps`，不要只看相机 SDK 元数据。

## 6. 测试

自动测试覆盖稳定死区、普通亮场、严重高光、暗场滞回、曝光优先增亮、曝光到顶后增益补偿和上下限保护。配置测试覆盖原生 AE 冲突和不安全曝光上限。部署后的实机收敛与持续帧率结果记录在 `08_reports/2026-08-04_Gemini305软件自适应曝光实机验证.md`。
