# Orbbec 软件自适应曝光（Gemini 305）

日期：2026-08-04（2026-08-06 更新帧驱动闭环）

## 1. 目标与范围

本功能解决 Gemini 305 原生自动曝光在场景切换时容易突然过曝，而固定手动曝光又需要人工反复调整的问题。

当前只在 `orangepi5pro-d12a4719/cam01`（192.168.66.133）的 Gemini 305 正式配置中启用。其他型号和其他发送端默认不受影响；本机 `rk3588-ubuntu/cam01` 已恢复固定手动曝光 `312/0`。方案保持 Orbbec SDK、RGB/Depth 配对、H.264 编码和媒体传输主路径不变。

## 2. 实机边界

测试档位为 RGB `1280x800@30 MJPG`、Depth `320x200@30`。

| 项目 | 实测结论 |
| --- | --- |
| 曝光 `80..325` | RGB 和 Depth 均可维持约 30fps |
| 曝光 `326..330` | 两路实际帧率下降到约 20fps |
| SDK `ACTUAL_FRAME_RATE` 元数据 | 在掉到 20fps 时仍可能错误报告 30，不可单独作为帧率依据 |
| gain `16..80` | 不直接降低帧率，但 40 以上已经明显增加高光与灰雾，48 以上纸面细节损失明显 |
| 原生自动曝光 | 静态场景可稳定在 exposure 157 / gain 16，问题主要出现在场景变化响应和测光策略 |
| AE ROI / AE max gain | 当前固件无法形成可靠限制，不作为正式控制手段 |

正式自适应范围使用 exposure `1..300`、gain `0..80`。曝光上限与实测 30fps 临界值 326 保留余量；控制器优先调整 exposure，只有曝光达到上限后才增加 gain。Gain 80 只是近全黑环境的兜底上限，普通室内场景实测稳定在 gain 32。

## 3. 测光与控制

调节期间每 50ms、稳定期间每 200ms 从相机原始 MJPEG 帧无输入复制地解码一张约 `160x100` 灰度缩略图，只统计中央 80% 区域。对连续 5 个样本取时域中值，每次写入 SDK 后等待 250ms 并重新建立样本窗口，避免旧帧、LED/PWM 闪烁或单帧异常触发连续追写。正式编码仍直接消费原始 MJPEG，不新增逐帧 BGR 转换。

当前目标为：

- P50 主体亮度目标 120，P95 上部亮度目标 210，死区正负 10。
- P99 软高光阈值 225，高光像素阈值 235，允许中央 ROI 内最多 3% 小面积高光。
- 采用对数曝光域 PI 控制，`Kp=0.6`、`Ki=0.15`，微分项关闭，并有积分限幅和输出限速。
- 高光面积超限时其超限程度直接参与 PI 误差；曝光每次最大跨度 170，增益每档 16，增益回退按过曝面积分级。
- 高光保护进入后，只有高光比例回落到上限的 70% 以下才允许再次增亮。P99 软高光本身只限制继续增亮，不单独强制减亮。
- 所有输出严格限制在 exposure `1..300` 和 gain `0..80`，不改变 30fps 采集档位。

P50 负责主体观感，P95/P99 和高光面积负责亮部保护。PI 比例项提供响应速度，积分项消除持续小偏差，时域中值、亮度死区和高光迟滞共同抑制闪烁与相邻档位振荡。

## 4. 可靠性

- 配置默认关闭，只有显式启用的相机参与。
- 仅显式启用且识别到已验证 Orbbec 型号时创建控制器；当前正式配置只启用 Gemini 305。
- SDK 写入后进行属性回读；不一致视为失败，不提交控制状态。
- Gemini 305 启动后先完成 V4L2 手动模式校验，再通过 SDK 强制重下发并回读 RGB 控制，避免流启动后 gain 从配置 0 回到固件默认 16。
- 测光解码或属性写入失败只记录诊断并保持上一次手动值，不影响采集、编码、发送和重连。
- 重连后从中性基线 exposure 100 / gain 0 重新初始化，再恢复闭环。

## 6. 测试

自动测试覆盖稳定死区、普通亮场、严重高光、暗场滞回、曝光优先增亮、曝光到顶后增益补偿、P50/P95 联合约束、PI 防饱和、5 帧中值测光、高光迟滞、按削顶面积限速和上下限保护。配置测试覆盖原生 AE 冲突、不安全曝光上限、非法 PID 参数和重叠亮度目标。部署后的实机收敛与持续帧率结果记录在 `08_reports/2026-08-04_Gemini305软件自适应曝光实机验证.md`。

## 7. SV1301S_U3 参数

本机 `SV1301S_U3 / RD3013 / SDK 1.10.27` 的 SDK 属性范围为 exposure `1..5000`、gain `0..100`。但属性可写范围不等于 30fps 安全范围。`1920x1080@30 MJPG + 320x200@30 Y12` 实测 exposure 300、312、325、333、334 可维持约 30fps，350 时 RGB 已下降到约 27fps。

该型号的控制器支持和 30fps 安全边界仍保留在代码中，但按本次现场范围调整，正式配置没有启用闭环，继续使用 exposure `312`、gain `0`。此前的软件闭环试验参数和结果仅保留在历史实机报告中，不代表当前运行配置。

## 8. Gemini 305 帧驱动闭环

2026-08-06 将 133 的测量和执行周期解耦。RGB 30fps 下每帧（约 33ms）允许进入测光；SDK 写入曝光或增益后，按实际 RGB 帧计数丢弃 3 帧未稳定反馈，再收集 3 帧并取时域中位数。因此最快约每 6 帧（约 200ms）执行一次控制，而不是每帧追写相机属性。

新增配置项：

- `discard_frames_after_adjustment`：属性写入后不参与闭环的 RGB 帧数，133 使用 3。
- `direction_reversal_samples`：普通控制方向反转所需的连续测量窗口数，133 使用 2。

普通增亮转减亮或减亮转增亮需要连续两个窗口确认，抑制反馈延迟造成的反向过冲。中央区域大面积严重削顶仍可绕过方向确认立即减亮。其他设备未配置这些字段时分别使用 0 和 1，保持原行为。

133 当前使用 3 帧中值窗口、曝光最大步长 60、增益最大步长 6、P50 目标 110，死区为正负 10。大误差使用 `Kp=0.5` 快速推进；进入死区后立即保持，避免为 1..2 级亮度误差长时间细调。RGB/Depth 保持约 30fps。
