
发送端依赖 Orbbec ARM64 SDK，SDK 实体不进入 GitHub 仓库。多发送端现场以 `<sender_id>_<camera_id>` 作为接收端唯一 key，任何改动都必须避免与其他发送端冲突。当前 RK3588 现场配置使用 `sender_id: orangepi5pro-66-133`，接收端地址 `192.168.66.196`，默认交付配置为 `06_configs/sender_rk3588-01_one_camera.json`，当前预期稳定运行一路 RGBD，默认相机为 `cam02 / AY2MC31010W`。默认 RGB 保持 `1920x1080@30 MJPG -> H.264 12Mbps`，默认 Depth 使用 `320x200@30 y12 -> zlib`。运行中仍保留配置外 Orbbec 设备热插拔能力，可自动分配 `cam03` / `cam04`，但多路不作为默认交付目标。Orange Pi 5 Pro 现场单路配置的运行规格也跟随默认 Depth 档，但身份字段必须保留 `sender_id=auto -> orangepi5pro-b439137c` 与 `camera_id=cam02`，不要临时改成 `orangepi5pro-66-206_cam01`，否则接收端 key 改名会导致 Web 预览和录制控制看起来像没收到流。2026-06-05 现场枚举确认 `SV1301S_U3 / AY2MC31010W` 最低 Depth profile 为 `320x200@5 y11/y12`，最高 Depth profile 为 `1280x800@30 y11/y12`，单路最高 Depth 测试配置为 `06_configs/sender_rk3588-01_cam02_depth_max.json`。2026-06-05 单路最高 Depth 档断开前有效采样为 RGB/Depth 约 30fps、总网络约 74.5Mbps、send failure 为 0。2026-05-29 历史多路容量测试中，3 路可运行但会出现 media TCP 背压丢包；详见 `04_docs/06_发送端运行使用手册_v3.md`。
