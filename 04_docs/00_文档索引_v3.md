发送端依赖 Orbbec ARM64 SDK，SDK 实体不进入 GitHub 仓库。多发送端现场以 `<sender_id>_<camera_id>` 作为接收端唯一 key，任何改动都必须避免与其他发送端冲突。当前 RK3588 现场配置使用 `sender_id: orangepi5pro-66-133`，接收端地址 `192.168.66.196`，默认交付配置为 `06_configs/sender_rk3588-01_one_camera.json`，当前预期稳定运行一路 RGBD，默认相机为 `cam02 / AY2MC31010W`。默认 RGB 保持 `1920x1080@30 MJPG -> H.264 12Mbps`，默认 Depth 使用 `320x200@30 y12 -> zlib`。运行中仍保留配置外 Orbbec 设备热插拔能力，可自动分配 `cam03` / `cam04`，但多路不作为默认交付目标。Orange Pi 5 Pro 现场单路配置的运行规格也跟随默认 Depth 档，但身份字段必须保留 `sender_id=auto -> orangepi5pro-b439137c` 与 `camera_id=cam02`，不要临时改成 `orangepi5pro-66-206_cam01`，否则接收端 key 改名会导致 Web 预览和录制控制看起来像没收到流。2026-06-05 现场枚举确认 `SV1301S_U3 / AY2MC31010W` 最低 Depth profile 为 `320x200@5 y11/y12`，最高 Depth profile 为 `1280x800@30 y11/y12`，单路最高 Depth 测试配置为 `06_configs/sender_rk3588-01_cam02_depth_max.json`。2026-06-05 单路最高 Depth 档断开前有效采样为 RGB/Depth 约 30fps、总网络约 74.5Mbps、send failure 为 0。2026-05-29 历史多路容量测试中，3 路可运行但会出现 media TCP 背压丢包；详见 `04_docs/06_发送端运行使用手册_v3.md`。

2026-06-05 时间显示约定：Web Monitor 可读时间统一按北京时间 UTC+8 显示到秒，桌面 GNOME 时钟也显示到秒；协议、API 和落盘中的微秒级 Unix 时间戳保持原始值，用于 RGB/Depth 和多发送端时间线对齐。

2026-06-08 多发送端时间戳同步方案：跨设备对齐不以北京时间显示为准，应统一使用局域网 chrony 时间源，并以接收端 `frames.csv` 中的 `frame_system_timestamp_us` 作为配对入口；详见 `04_docs/11_多发送端时间戳同步与对齐方案_v3.md`。

2026-06-09 树莓派发送端现场问题与处理：涵盖 Wi-Fi 守护误判、接收端多客户端背压、USB 线缆与 `usbfs_memory_mb` 对高档位 Depth 的影响，以及当前树莓派建议稳定配置；详见 `04_docs/12_树莓派发送端现场问题与处理记录_2026-06-09.md`。

2026-06-11 RGB 传输回压坏帧处理：正式录制默认关闭大体量 debug/raw 落盘；发送端在 RGB 传输失败后等待下一帧 IDR，再恢复发送非关键帧，避免 H.264 参考帧链断裂扩散；详见 `04_docs/17_RGB传输回压坏帧排查与整改说明_2026-06-11.md`。

2026-06-15 Gemini 305 树莓派适配：Gemini 305 在当前 Orbbec SDK v1 路径下不可枚举，本次新增 V4L2/UVC 采集后端并使用 `06_configs/sender_raspberrypi-01_gemini305_v4l2.json`，当前现场档位为 RGB `1280x800@30 MJPG`、Depth `320x200@30 Z16`；详见 `04_docs/18_Gemini305树莓派V4L2适配说明_2026-06-15.md`。

2026-06-18 Gemini305 SDK v2 深度采集修复：Gemini305 正式路径改为 Orbbec SDK v2，树莓派配置保持 RGB `1280x800@30 MJPG`、Depth `1280x800@30 Y16`；V4L2 Depth 低帧率问题确认为后端错误，不再作为正式采集方式。发送端新增 SDK v1/v2 自动选择、深度异步 zlib 压缩队列、watchdog 单实例锁，Gemini305 默认 RGB 曝光保持手动 `exposure=156/gain=16` 并设置 `auto_exposure_priority=0`；详见 `04_docs/26_Gemini305树莓派SDKv2深度采集修复_2026-06-18.md`。
