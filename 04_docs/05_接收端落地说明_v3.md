# 接收端落地说明 v3

## 1. 当前实现范围

接收端已经落地为两个进程：

1. `gemini_receiver`：C++ 核心接收与录制服务。
2. `09_web_monitor/server.py`：FastAPI Web/REST 监控服务。

C++ 服务负责：

1. UDP `50011` 接收发送端状态 JSON。
2. TCP `50010` 接收媒体二进制 packet。
3. 本地 HTTP `127.0.0.1:18080` 提供状态和录制控制。
4. 按 `/home/fz/Desktop/nas/<camera_key>/<YYYY-MM-DD>/<HHMMSS>/` 写录制切片。
5. RGB 不重编码封装为 `rgb.mp4`，按实测到达帧率写入容器，并保留 `rgb_debug.h264`。
6. Depth 按 `gray16le` 输入 FFmpeg，按实测到达帧率封装为 `depth.mkv + FFV1`，并保留 `depth_debug.raw`。
7. 生成 `meta.json` 和 `frames.csv`。

FastAPI 服务负责：

1. 提供浏览器页面。
2. 转发 REST 控制到 C++ 本地管理接口。
3. 默认监听 `0.0.0.0:8080`。

## 4. 当前验证结果

在当前机器上已经验证：

1. `cmake` 可配置工程。
2. `gemini_receiver` 可编译运行。
3. FastAPI Web 可启动。
4. 已收到真实发送端 `orangepi5pro-01/cam01` 的状态和媒体帧。
5. `start-all` / `stop-all` 可控制录制。
6. NAS 目录下已生成切片文件。
7. `rgb.mp4` 可被 `ffprobe` 识别为 H.264 1080p，封装 fps 接近 `frames.csv` 中的 RGB 到达 fps。
8. `depth.mkv` 可被 `ffprobe` 识别为 `FFV1 gray16le 640x400`，封装 fps 接近 `frames.csv` 中的 Depth 到达 fps。

## 5. 当前发现的问题

当前接收端录制链路已经闭环。实测本机收到的发送端 RGB/Depth 到达帧率可能低于目标 30fps，本地播放观感以真实到达帧率为准。

排查时使用：

```bash
./05_tools/analyze_segment_fps.py <segment_dir>
```

重点对比 `media fps`、`arrival fps` 和 `intervals`。如果 `arrival fps` 只有十几帧，需要优先排查发送端采集、编码、Depth 压缩、预览和网络链路，而不是只改接收端封装参数。
