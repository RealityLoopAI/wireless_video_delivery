# 树莓派 Wi-Fi Guard 无画面根因与修复

日期：2026-06-17

## 现象

树莓派 `gemini-sender.service` 显示 active，但接收端和网页预览看不到 `raspberrypi-01_cam01` 画面。

典型日志：

```text
wifi guard connect failed before child start: 无法在 wlan0 上启用 Wi-Fi 连接 土著拯救器-5G
```

## 根因

树莓派发送端的 watchdog 在启动 `gemini_sender` 子进程前会先执行 Wi-Fi guard。旧配置把默认 Wi-Fi 连接名写死为旧现场 SSID：

```text
GEMINI_SENDER_DEFAULT_WIFI_CONNECTION=土著拯救器-5G
```

现场网络切到 `666666` 后，NetworkManager 无法在 `wlan0` 上启用旧连接名，watchdog 一直停在启动前检查阶段，没有真正拉起采集和发送进程。因此服务看起来在运行，但没有媒体流。

## 修复

代码默认策略改为：

- 默认只要求 Wi-Fi 频率不低于 `5000MHz`。
- 不默认写死 SSID。
- 只有现场必须锁定某个 AP 时，才显式设置 `GEMINI_SENDER_DEFAULT_WIFI_CONNECTION` 或 `GEMINI_SENDER_WIFI_CONNECTION`。

涉及入口：

- `05_tools/sender_wifi_guard.sh`
- `05_tools/sender_watchdog.sh`
- `05_tools/start_sender.sh`
- `05_tools/start_sender_preview.sh`

systemd 服务建议保留：

```text
Environment=GEMINI_SENDER_DEFAULT_WIFI_MIN_FREQ_MHZ=5000
```

systemd 服务不要默认保留：

```text
Environment=GEMINI_SENDER_DEFAULT_WIFI_CONNECTION=...
```

## 排查命令

查看服务是否真正拉起子进程：

```bash
systemctl status gemini-sender.service --no-pager
pgrep -af 'gemini_sender|sender_watchdog'
```

查看 Wi-Fi 是否在 5GHz：

```bash
nmcli -t -f ACTIVE,SSID,FREQ,DEVICE dev wifi list ifname wlan0 | grep '^yes'
iw dev wlan0 link
```

查看 watchdog 日志：

```bash
tail -n 80 /home/berry/Desktop/wireless_video_delivery/08_reports/sender_logs/sender_stdout.log
```

## 防复发原则

换 AP、换路由器、CPE/AP 拆分或重命名 Wi-Fi 后，不需要改仓库代码。优先让 NetworkManager 自动连接现场 Wi-Fi，发送端只校验 5GHz 频段。

如果某次测试确实需要锁定 SSID，用 systemd drop-in 或临时环境变量覆盖，不要把现场 SSID 写回默认脚本。
