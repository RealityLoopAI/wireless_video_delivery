## 7. 运行状态判断

### 7.1 sender 正常状态

sender 正常时日志类似：

```text
state=RUNNING fps_in=14.3 fps_out=180+ bitrate=1500kbps queue=0 drops=0 reconnect=0
```

含义：

1. `fps_in` 是采集帧率。
2. `fps_out` 是发送出去的 RTP 包输出速率统计，不是显示帧率。
3. `bitrate` 是当前估算码率。
4. `reconnect=0` 表示没有发生异常重连。

### 7.2 receiver 正常状态

receiver 正常时日志类似：

```text
state=RUNNING fps_out=14.3 latency=93.5ms rx=7000+ lost=0 queue=1
```

含义：

1. `fps_out` 是接收端显示帧率。
2. `latency` 是估算端到端延迟。
3. `rx` 是累计收到的 RTP 包数。
4. `lost` 是累计丢包数。

## 10. 常见问题与处理

### 10.1 `OB_USB_STATUS_ACCESS`

原因：

当前用户没有 USB 访问权限。

处理：

```bash
sudo bash /home/berry/orbbec/pyorbbecsdk-main/scripts/install_udev_rules.sh
```

然后重新插拔相机。

### 10.2 `OB_USB_STATUS_BUSY`

原因：

相机被其他进程占用。

常见占用者：

1. `color_viewer.py`
2. 旧的 sender 进程
3. 其他测试脚本

可先检查：

```bash
pgrep -af 'color_viewer.py|run_sender.py|hello_orbbec.py'
```

### 10.3 接收端端口占用

现象：

`OSError: [Errno 98] Address already in use`

原因：

接收端旧进程没退出，仍占用 `5600` 端口。

处理：

```bash
pkill -f 'run_receiver.py --config'
```

### 10.4 sender 能开流但 receiver 没数据

检查项：

1. `sender.json` 的 `remote_ip` 是否正确。
2. 接收端和发送端是否在同一网段。
3. 防火墙是否拦截 UDP `5600`。
4. receiver 是否先于 sender 启动。

### 10.5 实际帧率不到 30fps

优先检查：

1. 相机是否工作在 USB3.0 链路。
2. 当前相机输出格式是否受限。
3. 树莓派端 CPU 是否被占满。
4. 无线网络是否抖动严重。

## 11. 建议执行顺序

实际部署建议按下面顺序执行：

1. 安装 udev 规则并确认相机权限。
2. 使用 `hello_orbbec.py` 验证设备访问。
3. 先做本机回环测试。
4. 回环稳定后，再改 `sender.json` 做跨设备无线测试。
5. 无线测试稳定后，再安装 systemd 自启动服务。
