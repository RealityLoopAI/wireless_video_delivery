# Gemini 305 软件自适应曝光实机验证

日期：2026-08-04

## 测试对象

- sender：`orangepi5pro-d12a4719`（192.168.66.133）
- camera：Orbbec Gemini 305
- RGB：`1280x800@30 MJPG`
- Depth：`320x200@30`

## 实现前边界测试

- exposure 325 时 RGB/Depth 仍约 30fps。
- exposure 从 326 起 RGB/Depth 实际降至约 20fps。
- gain 16 的细节和高光最好；32 尚可；40 开始接近亮度边界；48 及以上明显损失纸面细节。
- 固定 50Hz 电源频率、关闭背光补偿的短时亮度波动最小，平均亮度没有明显变化。
- 原生 AE 在固定场景可稳定，但不具备可靠的最大 gain 和有效 AE ROI 约束。

## 源帧测光基线

```text
p95=202
p98=204
p99=208
pixels>=245: 0.00107%
```

因此正式目标选择 P95=200、死区=8、高光阈值=245。

- 稳定阶段日志中的高光占比为 0.00%，未触发高光压制；属性写入/回读失败数为 0。

- 当前压缩后媒体码率约 RGB 6.0Mbps、Depth 5.0Mbps；自适应测光没有改变 RGB/Depth 档位或传输格式。

结论：软件闭环可在不调用 Gemini 305 原生 AE 的情况下根据现场亮度自动调节，并通过 exposure 200 / gain 32 的硬上限保留 30fps 余量。该结果是短时实机稳定性验证，不替代后续昼夜和强逆光场景长测。

## 二次调优：主体亮度与响应线性

首版配置在当前白纸占比较大的场景暴露出两个问题：

1. exposure/gain 下限为 `80/16` 时，P95 仍约 235，控制器已经到下限但无法继续回压。
2. 将下限放宽到 `20/0` 后，只看 P95 会收敛到约 `24/0`、P95 约 203，但中间调和背景明显过暗。P95 达标不代表主体观感正确。

因此正式控制改为 P50/P95/P99 联合测光：P50=150 控制主体亮度，P95=225 作为亮部上限，P99=245 和高光比例 0.25% 处理严重高光。正式范围调整为 exposure `20..300`、gain `0..32`，优先使用曝光，曝光到顶后才增加增益。

响应策略同步调整：

- 稳定状态测光周期从 500ms 缩短到 100ms，场景变化最迟约 100ms 被发现。
- 每次写入 SDK 后等待 200ms 再闭环，避免用尚未生效的旧画面反复累加曝光。
- 暗场确认从连续 3 次缩短为 1 次。
- 普通增亮和减亮按 `目标亮度 / 当前亮度` 估算目标 exposure，并以每次最多 16 的固定斜率逼近；目标附近自动缩小步长。
- 严重高光使用 24 的快速回压，并立即清除不必要的 gain。
- P50 死区最终使用正负 8；快速检测和固定斜率负责响应速度，较宽死区负责抑制目标附近噪声。

最终版本在 16:59:28 部署。当前暗场启动时从 `130/0` 依次调整到 `146/0`、`162/0`、`178/0`、`194/0`、`210/0`、`226/0`、`242/0`、`258/0`、`274/0`、`290/0`、`300/0`，约 2.2 秒完成近似匀速曝光爬升，随后仅补偿到 gain 2。没有再出现连续追写后的反向大幅回摆。

稳定阶段实测：

```text
exposure=300, gain=2
source p50=145..146, p95=199, p99=216
RGB input/send=29.9..30.0fps
Depth input/send=29.9..30.0fps
adaptive failures=0
corrupt frames=0
send failures=0
```

接收端 `640x400` 预览中透明瓶体、标签和背景物体可辨认，P99 低于高光阈值，没有高光削顶。

17:08:39 现场又发生一次亮场切换。控制器先将 gain `8 -> 4 -> 0`，随后将 exposure 按 `300 -> 284 -> 268 -> 252 -> 239 -> 223 -> 207 -> 191 -> 175 -> 159 -> 143 -> 128 -> 119 -> 114` 回压，约 4 秒完成；大误差阶段基本保持每次 16 的固定斜率，接近目标后自动缩小到 15、9、5。最终稳定在 P50=154、P95=172、P99=176，RGB/Depth 约 30fps，失败计数为 0。该现场变化验证了双向响应；仍不等同于固定光源和照度计条件下可重复的实验室阶跃测试。

17:10:46 设备整机重新上电后，正式配置和 systemd 自启动均正常恢复。暗场补偿阶段发现普通 gain 原先使用 `+2/-4` 的不对称步长，会在目标边界附近产生锯齿。最终将普通 gain 调整统一为 `+2/-2`，严重高光清除逻辑不变；同时将 P50 死区恢复为正负 8，避免源画面统计抖动触发无意义反向调节。

后续服务重启还发现 Gemini 305 流启动后 SDK 帧元数据可能从已配置的 gain 0 回到固件默认 16。原有 2 秒延迟流程只通过 V4L2 校验和重下发手动曝光，SDK 属性状态未再次同步；若此时 P50 偏暗但 P95 已进入高光保护，闭环不会产生写操作，错误 gain 会长期保留。最终在 V4L2 手动模式校验成功后增加 SDK RGB 控制整组重下发与回读，确认基线正确后才结束暖机并发布媒体。

## 三次调优：小面积亮区与主体亮度折中

18:00 后的电子秤亮屏场景显示，原控制器会从 `130/0` 连续提升到 `300/32`。此时 P50 仅约 125，P95/P99 约 235，但 `>=245` 的像素比例为 0；因此小亮屏肉眼已经丢失细节，原有 245 阈值却无法触发。Gain 还在 24..32 间往复调整，说明只用 P50 追主体亮度和用 P95 禁止继续提亮不足以形成稳定回路。

本轮修正如下：

- P95 超过 `target_p95_luma + luma_deadband` 后主动回退，不再只停止增亮。
- 增亮步长受 P95 剩余余量限制；P95/P99 接近上限时保持，避免 Gain 在两个档位间反复跳变。
- 新增 `soft_highlight_luma`，Gemini 305 配置为 235，用 P99 捕捉小于 P95 覆盖范围的亮屏、白纸和反光区。
- 新增 `soft_highlight_exposure_floor=130`。P95/P99 软高光先降 Gain，再渐进降曝光，但不会因局部亮区把主体压到过暗。P99>=245 的严重削顶或 P50 整体过亮仍可继续低于 130。

18:30 最终版本部署并重启后，当前高反差场景稳定在：

```text
exposure=130, gain=0
source p50=58, p95=202..205, p99=235
RGB input/send=29.8..30.0fps
Depth input/send=29.8..30.0fps
adaptive failures=0
RGB/Depth send failures=0
```

接收端 `640x400` 预览中电子秤数字恢复可读，周边设备和环境仍可辨认。该结果是“小面积亮区细节优先，主体不低于实测基线”的明确折中；单次全局曝光无法同时让自发光屏和暗背景都达到 P50 目标。

验证：`adaptive_exposure_controller_test` 与全部 sender 配置校验通过，133 实机 SDK 属性写入和回读无失败，未影响 RGBD 30fps 采集和发送。

## 五次调优：按 RGB 帧等待反馈

2026-08-06 排查确认，原 50ms 测量、100ms settle 参数会在相机画面尚未反映上一次属性写入时继续控制，实机出现 exposure `3..300` 和 gain `0..49` 的大幅往复。仅将 settle 拉长到 700ms 可以消除振荡，但再次决策约需 1.1 秒，场景切换响应过慢。

最终改为每 33ms 允许测光，写入后丢弃 3 个 RGB 帧，再使用后续 3 帧中位数决策；普通方向反转要求连续两个窗口确认，大面积严重过曝保留快速下降。133 实机从 exposure 100 启动约 2 秒到 206，随后稳定在 211/0，连续观察未出现反向振荡。发送端约占 1.72 个 CPU 核，RGB/Depth 输入和发送均保持约 30fps。

## 四次调优：PI、时域测光与高光迟滞

2026-08-05 对比了原比例控制、严格高光 PI 和均衡高光 PI 三组方案。

- 原比例控制在 LED 灯条场景受帧间闪烁影响，低曝光档位持续加减，参数写入次数过多。
- PI + 5 帧中值能明显减少追写，但允许高光面积 0.25% 时会为不到 1% 的灯条把整帧压到 exposure 1..2，主体严重过暗。
- 最终方案使用 P50=120、P95=210、高光阈值 235、允许面积 3%，并加入 70% 退出迟滞。P99 软高光只限制继续增亮，不单独强制减亮。
- 大面积过曝程度直接参与对数域 PI 误差，增益回退步长按过曝面积分级，避免从 80 直接降到 0 造成暗闪。
- 中性启动值为 exposure 100 / gain 0，正式边界为 exposure 1..300 / gain 0..80；gain 80 仅用于极暗场景兜底。

实机最终亮场从首个有效测光样本到稳定用时约 3 秒，共 6 次调整，收敛为：

```text
exposure=300, gain=32
P50=120..121, P95=208..209, P99=235
highlight_fraction=2.72%..2.76%
RGB input/send=29.8..30.0fps
Depth input/send=29.8..30.0fps
adaptive failures=0
RGB/Depth send failures=0
```

参数稳定后连续观察超过 10 分钟，adjustment count 保持在 6，未再出现相邻档位振荡。近全黑场景中，从 100/0 收敛到 300/80 约 4 秒，帧率仍为约 30fps；由于物理光量不足，继续增加 gain 只会增加噪点，因此不再扩大上限。

运行负载为约 1.39 CPU 核、95MB RSS、62.8°C。观察期间相机源产生 2 张缺少 JPEG SOI/EOI 标记的坏帧，已由现有 MJPEG 校验丢弃，未传输坏帧；该现象与曝光属性写入无时间相关性。
