# 长时间录制全链路根治与验证归档

日期：2026-07-21

## 1. 整改结论

本轮针对 2026-07-20 长测暴露的接收端/NAS 公共反压、MP4 收尾、离线分片、文件描述符继承、RGB 断线恢复和 Gemini 305 重连暗帧完成代码整改，并部署到当前五台在线 sender 与 receiver。

短时现场验收和故障注入均通过。该结论证明本轮根因已被隔离和覆盖，但不替代 4 小时以上无人值守耐久复测。硬件供电、USB/xHCI 复位、FOV、佩戴结构、电量显示、颜色标定和无同步线条件下的曝光级硬同步不属于本次纯软件整改可消除的范围。

## 2. 已修复问题

### 2.1 receiver/NAS 反压

1. 实时媒体先写 receiver 本地 ext4 staging，不再直接写 CIFS。
2. receiver 只负责快速关闭 fragmented MP4、Depth、CSV 和元数据。
3. 普通 MP4 无损重封装和 NAS 上传移到独立低优先级 systemd cgroup。
4. NAS 不可用时保留本地完整分片并持久重试。
5. 上传限速、积压段数、积压字节、最老任务、失败数和当前任务均可观测。
6. `write_debug_h264=false` 时不再打开和双写完整 RGB H.264。

### 2.2 文件与进程生命周期

1. receiver 的 `system`/`popen` 路径改为 `posix_spawn`。
2. pipe 使用 `O_CLOEXEC`，子进程关闭所有无关 fd，避免 FFmpeg 长期持有已删除录制文件和产生 `.__smb*`。
3. 上传器使用 `flock`，进程死亡后锁由内核释放。
4. NAS 复制先进入隐藏目录，校验后原子改名，ready 标记最后写入。
5. 上传中断留下的隐藏临时目录会在下次重试时清理。
6. 支持 `test_Short_0048_` 等任意合法文件前缀。

### 2.3 sender 离线和 RGB 恢复

1. receiver 增加独立录制维护线程，分片轮转和媒体空闲收尾不再依赖新包到达。
2. sender 重连后创建新分片，旧分片独立完成收尾。
3. RGB 发送失败后不再重试旧 P 帧；旧 job 立即丢弃并请求新 IDR。
4. 实际发送前再次执行关键帧保护，覆盖排队期间发生连接失败的竞态。
5. heartbeat 增加采集/发送 FPS、发送失败和传输恢复丢帧累计计数。

### 2.4 Gemini 305 恢复暗帧

1. Gemini 305 pipeline 启动或重建后默认进入 3 秒发布暖机。
2. 暖机期间继续采集并更新 watchdog，但 RGB/Depth 不编码、不发送、不录制。
3. 手动曝光模式在延迟重设并验证后才解除门控。
4. 暖机结束主动请求 IDR，避免首个发布包依赖旧参考帧。

### 2.5 部署一致性

1. sender 与 receiver 分别计算组件级 `build_source_hash`，接收端改动不再污染 sender 版本判断。
2. receiver 状态保存 sender commit/source hash、输入/发送 FPS、失败计数、media session 和当前 segment 信息。
3. 当前五台 sender 的组件源码哈希一致。

## 3. 自动化验证

x86 receiver 实机执行四项 CTest：

```text
receiver_hardening_integration             PASS
sync_input_guard_unit                      PASS
recording_uploader_fault_injection         PASS
receiver_staging_pipeline_integration      PASS
```

覆盖内容包括：

1. 真实 FFmpeg fragmented MP4 生成和普通 MP4 无损转换。
2. NAS 不可用、上传中途 SIGTERM、服务重启和自动续传。
3. 带前缀录制标记的发现与发布。
4. 空闲 1 秒自动关闭旧分片、重连后恢复录制。
5. 轮转后递归检查 receiver/FFmpeg 不存在已删除录制 fd。
6. CSV、ready 标记、Depth 可读性和 NAS 原子发布。

同一套四项测试在 AddressSanitizer 与 UndefinedBehaviorSanitizer 下全部通过。sender ARM64 原生构建和配置校验通过。

最终代码还执行了 `clang-analyzer-*` 和 `bugprone-*` 静态检查。新发现的预览解码器移交后控制流已改为明确的空指针/IDR 状态机；上传器同时增加了 marker 文件名边界校验。sanitizer 慢速环境暴露的状态缓存测试竞态也已按 API 允许短暂 stale 的语义修正并重测通过。

## 6. 剩余验收与边界

下列项目不是本轮代码尚未写完，而是仍需时间或硬件条件验证：

1. 重新执行至少 4 小时、跨 16 次 15 分钟边界的无人值守耐久录制。
2. NAS 人为中断 1 至 5 分钟的现场链路测试；自动测试已覆盖同一状态机。
3. 当前本地可用于 backlog 的容量约 43 GiB，按 80.85 Mbit/s 约为一小时级，NAS 长时间离线仍会触发磁盘水位保护。
4. Gemini 305 的重复 xHCI/USB reset 需要继续从供电、线材、控制器、固件和散热层排查；软件只能缩短并隔离恢复影响。
5. 无硬件触发/同步线时不能承诺画面曝光级硬同步，仍使用 chrony、CLOCK_SYNC、`global_timestamp_us` 和离线内容补偿。
6. 两路偏黄需要统一光源和色卡标定，不应继续凭网页主观调白平衡。
