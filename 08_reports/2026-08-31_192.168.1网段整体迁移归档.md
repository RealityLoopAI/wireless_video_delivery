# 192.168.1 网段整体迁移归档

## 目标

现场网络由 `192.168.66.0/24` 迁移到 `192.168.1.0/24`，接收端保留固定尾号 `196`，最终地址为 `192.168.1.196`。不保留旧地址 `192.168.66.196`。

## 最终地址

- 接收端虚拟机：`192.168.1.196/24`
- 接收端网关：`192.168.1.1`
- NAS：`192.168.1.89`
- 本机 `rk3588-ubuntu`：当前由 DHCP 获取 `192.168.1.94`
- Web 预览：`http://192.168.1.196:8080/`
- 媒体 TCP：`192.168.1.196:50010`
- 状态 UDP：`192.168.1.196:50011`
- Clock Sync UDP：`192.168.1.196:50012`

## 已完成修改

1. 接收端 `ens3` 改为固定 `192.168.1.196/24`，删除临时旧网段副地址。
2. 接收端 CIFS 挂载从 `//192.168.66.150/video_database` 改为 `//192.168.1.89/video_database`。
3. 仓库中所有当前 sender 配置的 media/status/clock sync 接收地址改为 `192.168.1.196`。
4. sender chrony 默认时间源改为 `192.168.1.196`。
5. receiver chrony 默认允许网段改为 `192.168.1.0/24`。
6. 本机已删除迁移期间临时添加的 `192.168.66.85` 副地址和主机路由。

## 现场验证

- 接收端媒体、状态、Clock Sync、Admin 和 Web 端口均正常监听。
- Web 访问返回 HTTP 200，receiver admin 状态不过期。
- 本机 RGB 和 Depth 均稳定发送约 30 FPS，发送失败为 0。
- RGB 码率约 `11-12 Mbps`，Depth 码率约 `2.8 Mbps`。
- Clock Sync 重置后 offset 约 `0.47 ms`，delay 约 `2.8 ms`。
- 本机 chrony 以 `192.168.1.196` 为唯一时间源，验证时系统时间误差约 `0.15 ms`。
- NAS CIFS 已挂载且可写，媒体接收端已恢复运行。
- 旧网络中积压的 28 个音频片段已全部发布到 NAS，当前 pending 为 0。

## 待上线设备

迁移时除本机外的发送端均未在新旧网段应答，因此无法现场部署。这些设备上线后必须：

1. 连接 `192.168.1.0/24` 新网络并获取新地址。
2. 拉取本次提交或同步对应 sender 配置。
3. 本机编译后重启 sender 服务。
4. 重新执行 `setup_sender_chrony_client.sh 192.168.1.196`。
5. 验证媒体 30 FPS、Clock Sync healthy 和 chrony synchronized。
