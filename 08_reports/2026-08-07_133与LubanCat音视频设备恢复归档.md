# 133 与 LubanCat 音视频设备恢复归档

日期：2026-08-07

## 133 音频

- 当前录音设备：`USB PnP Sound Device`。
- 当前播放设备：`USB2.0 Device`。
- systemd drop-in 按 ALSA 卡型号动态解析 `plughw:CARD=...,DEV=0`，不依赖热插拔后会改变的 card 数字。
- 麦克风增益 85%、AGC 关闭，音箱 PCM 100%。
- HTTP TTS `POST /api/tts/speak` 返回 `accepted=true` 用时 39 ms；播放完后 `arecord` 成功重建，主服务 PID 不变且 `NRestarts=0`。

## LubanCat 音频

- 设备：`SM15 M1 USB audio`，同一 ALSA 卡完成录放。
- 安装 Vosk、WebRTC VAD、Edge TTS 依赖和中文小模型，已启用 `xiaohuan-wake.service` 及用户 linger。
- SM15 的 AEC 可合法输出全零 PCM，专用 drop-in 设置 `XIAOHUAN_ZERO_AUDIO_RESTART_SECONDS=0`，避免数字静音被误判为断流；ALSA 读取超时仍会触发真实恢复。
- HTTP TTS 返回 `accepted=true` 用时 29 ms；播放后录音恢复，`NRestarts=0`。
- systemd 单元的工作目录和启动路径改用 `%h`，同一单元可用于 `orangepi`、`cat` 等不同用户。Edge TTS 缓存使用程序的 `Path.home()` 默认值，不再硬编码 `/home/orangepi`。

## LubanCat 视频断流

- Gemini 305 启动时曾以 USB 3.0 5 Gbps 枚举。
- 18:13:37 内核记录 SuperSpeed 设备断开，随后 USB2 伴随端点连续出现 `error -32`、`error -71`、端口断电重试和 `unable to enumerate USB device`。
- sender service 和 watchdog 均在运行，但设备已从 USB 总线消失，重启 sender 子进程无法恢复。
- 重启 LubanCat 复位 xHCI 后，相机重新以 5 Gbps 枚举，RGB/Depth 均恢复约 30 FPS。接收端 RGB JPEG 和 Depth BMP 预览接口均返回 HTTP 200，实际图像非空。
- 上述恢复只维持约 1 分钟，随后 LubanCat 连 ping/SSH 也同时消失。该板的 USB Wi-Fi、SM15 和 Gemini 305 共用同一 xHCI，因此相机端口再次拖死控制器时会让整机在网络上离线。截至本次归档，该硬件故障未根治，需现场处理线缆/供电/接插件后再做持续测试。
- 该故障的根因位于 USB 线缆、接插件、供电或底板布线链路；软件可重试和报警，不能保证修复已无法枚举的物理设备。
