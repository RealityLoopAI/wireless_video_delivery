# 语音唤醒与 RTP 音频并行验证

日期：2026-07-29

## 目标

在 `192.168.66.133` 使用现有 USB 麦克风持续发送实时音频到 `192.168.66.32:50020`，同时保留本机“你好小环”和“拍照”识别。

## 实现

- 麦克风由一个 GStreamer pipeline 以 `48kHz/S16LE/单声道` 打开。
- `tee` 后的本机支路经独立 queue 重采样为 `16kHz`，继续进入原有 FFmpeg 语音滤波和 Vosk。
- 网络支路经独立 200ms leaky queue，编码为 `Opus CBR 64kbps`。
- RTP 参数为动态载荷类型 96、48kHz 时钟、20ms 帧、MTU 1200，并启用 Opus in-band FEC。
- 功能默认关闭，仅在 `133` 的 systemd drop-in 中启用。

## 验证

- Python 语法、Shell 语法和拍照/音频命令单元测试通过。
- 目标 Windows `192.168.66.32` 可达，ICMP 往返约 `3–6ms`。
- 临时使用 Linux 接收端 `192.168.66.196` 完成真实麦克风 RTP/Opus 闭环。
- 接收端成功解码出 `6.6s` WAV，采样率 `48kHz`，峰值约 `-11.7dBFS`，存在有效音频且无削波。
- 开启网络流后，通过 USB 音箱回放已知有效的真人“你好小环”样本，日志仍识别为 `你好 小环` 并完整进入固定回复和拍照命令窗口。
- Opus complexity 固定为 5；语音服务三进程合计约占一个 CPU 核心的 `21%`，折算为 8 核设备总算力约 `2.6%`，服务内存约 `149MB`。
- 验证后已恢复发送目标 `192.168.66.32:50020`。
- `xiaohuan-wake.service` 保持 active，本机识别支路仍为 `16kHz`。

Windows 最终播放效果需由下游工程师安装 VLC、放行 UDP 50020 并打开配套 SDP 后确认。
