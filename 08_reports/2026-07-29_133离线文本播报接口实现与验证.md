# 133 离线文本播报接口实现与验证

## 目标

在 `192.168.66.133` 的现有“小环”语音服务内增加局域网 HTTP 文本播报接口，同时
保留唤醒、拍照命令和 RTP/Opus 麦克风推流。远程文本和本地固定回复必须严格串行，
播放时不得把音箱声音重新识别或推送给音频接收端。

## 已实现

- 新增 `speech_service.py`，提供线程安全的统一语音 FIFO。
- 新增 `POST /api/tts/speak`，固定监听 `0.0.0.0:18082`。
- 请求必须包含 `request_id` 和 `text`，文本上限 500 字符。
- 同一进程生命周期内按 `request_id` 幂等去重。
- 队列容量 100；满队列返回 HTTP 429，不丢弃已受理任务。
- 入队立即返回 HTTP 202、`accepted`、`task_id` 和当前队列位置。
- 唤醒回复、拍照回复、远程文本共用同一严格 FIFO。
- 长文本按句切分，合成线程先生成首句；后续句子使用最多两个 PCM 分段的有界缓冲，
  不等待整段文本全部生成。
- 播放前终止当前 GStreamer/ffmpeg 麦克风管线，同时暂停 Vosk 和 RTP/Opus。
- 队列暂时清空 200ms 后重新打开麦克风，清空旧 VAD 片段并恢复识别、推流。
- 音箱失败最多重试 5 秒，随后丢弃当前任务并继续下一条。
- 服务继续由 `xiaohuan-wake.service` 管理，保持 `Restart=always` 和开机自启。

完整调用协议见：


## 后端选型

### sherpa-onnx VITS

设备原有 `sherpa-onnx 1.13.3`，已验证官方
`vits-melo-tts-zh_en` 中英模型。模型可正确生成中英混合语音，但在 133 同时运行
RGBD sender 时延迟过高：

| 线程 | 9 字中文 | 30 字中英混合 | 22 字中文 |
| --- | ---: | ---: | ---: |
| 1 | 5.161s | 12.546s | 12.828s |
| 2 | 3.208s | 7.510s | 7.539s |
| 4 | 3.389s | 7.975s | 7.849s |

因此保留 `XIAOHUAN_TTS_BACKEND=sherpa` 作为可选高质量方案，不设为默认。

模型来源：

```text
https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/vits-melo-tts-zh_en.tar.bz2
SHA-256: e58351ed7149f290a54534538badd4077cdbe6fddc964b24d0bee870415d1514
```

### eSpeak NG

默认选择 Ubuntu `espeak-ng 1.50` 的 `cmn` 普通话后端，并把拉丁字母片段通过 SSML
切换到 `en-us`。这是完全离线的轻量级共振峰合成，音色较机械，但满足本项目
“低延迟优先”的要求。

133 实测：

| 文本 | 合成耗时 | 音频时长 |
| --- | ---: | ---: |
| `数据采集已经完成。` | 44ms | 2.628s |
| `设备 camera 01 已连接，当前帧率是 30 FPS。` | 76ms | 5.261s |

依赖安装：

```bash
sudo apt-get install -y espeak-ng
```

官方项目：

```text
https://github.com/espeak-ng/espeak-ng
```


HTTP 提交：

```text

response time: 19.7ms

```

幂等重试：

```text
status: 202
duplicate: true
task_id: 与第一次相同
queue_position: 0

```

播放期间以 100ms 周期观测进程：

```text
播放前: gst=1, aplay=0
播放中: gst=0, aplay=1
播放后: gst=1, aplay=0
```

GStreamer 继续向 `192.168.66.113:50020` 发送 RTP/Opus。

覆盖：

- HTTP 参数校验和 UTF-8 JSON。
- 202 入队、幂等去重、完成后位置 0。
- 容量限制和 HTTP 429。
- 本地 WAV 与远程文本的严格 FIFO。
- 中英 SSML 转义。
- 音箱失败重试截止时间。
- 三连拍、近音命令和现有音频流命令回归。

## 已知限制

- `accepted=true` 只表示进入内存队列，没有任务完成查询接口。
- 队列和幂等记录不持久化，服务重启后清空。
- 接口按需求不做认证，只应暴露在可信局域网，不能映射到公网。
- 播放期间麦克风 RTP 会有与语音长度相同的主动空窗；这是避免回声进入下游的设计
  行为，不是网络断流。
- eSpeak 音色机械；需要更自然音色时可切换 sherpa，但必须接受当前设备更高的首句
  延迟，或单独增加 TTS 算力。
