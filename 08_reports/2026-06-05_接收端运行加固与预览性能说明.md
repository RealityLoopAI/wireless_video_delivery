# 2026-06-05 接收端运行加固与预览性能说明

## 1. 背景

2026-06-05 检查接收端时发现 C++ 接收端和 Web 监控均未运行，`18080` 管理接口拒绝连接，`8080` Web 页面不可用。

系统日志显示根因发生在 2026-06-04 18:51:12：

```text
systemd-oomd killed 39 process(es) in vte-spawn-*.scope
Failed with result 'oom-kill'
Current Memory Usage: 4.9G
```

当时接收端、Web 和 ffmpeg 预览进程挂在 GNOME Terminal 的 `vte-spawn-*.scope` 下。系统内存压力超过阈值后，`systemd-oomd` 杀掉了整个终端 scope，导致接收端相关进程一起退出。

## 2. 已落地加固

### 2.1 systemd 用户服务

新增脚本：

```text
05_tools/install_receiver_autostart.sh
05_tools/uninstall_receiver_autostart.sh
```

安装脚本会创建并启用：

```text
gwv3-gemini-receiver.service
gwv3-web-monitor.service
gwv3-receiver-log-rotate.timer
```

效果：

- 接收端和 Web 不再挂在终端 scope 下。
- 异常退出后由 systemd 自动重启。
- 登录用户后自动启动。
- 如果需要未登录也启动，可额外执行 `sudo loginctl enable-linger fz`。

### 2.2 内存上限

持久化服务设置：

```text
gwv3-gemini-receiver.service: MemoryHigh=3G, MemoryMax=4G
gwv3-web-monitor.service: MemoryHigh=384M, MemoryMax=512M
```

目的：

- 避免单个服务无限占用内存拖垮用户会话。
- 服务触发上限时由 systemd 重启，而不是连带终端和其他进程被 OOM 清理。

### 2.3 日志轮转

新增脚本：

```text
05_tools/rotate_receiver_logs.sh
```

默认规则：

```text
单个日志超过 256MB 后归档到 08_reports/receiver_logs/archive/
归档文件默认保留 30 天
timer 每 10 分钟检查一次
```

本次处理时已把旧日志归档：

```text
receiver.log
receiver_stdout.log
web_stdout.log
```

其中 `web_stdout.log` 曾因高频预览 HTTP 访问日志增长到约 3.3GB。

### 2.4 Web 访问日志关闭

`05_tools/start_receiver.sh` 启动 Web 时使用：

```text
uvicorn ... --no-access-log
```

避免每张预览图请求都写入 `web_stdout.log`。

### 2.5 接收端状态日志限频

C++ 接收端对常规状态消息进行限频：

```text
heartbeat / camera_announce / camera_offline 每路最短 60 秒记录一次
event / warning / error 仍实时记录
```

避免多路发送端长时间运行时每秒刷大量状态日志。

## 4. ffmpeg 预览解码现状

当前网页 RGB 预览使用 ffmpeg 软件解码：

```text
ffmpeg -f h264 -i pipe:0 -vf fps=10,scale=640:-2 -q:v 3 -f image2pipe -vcodec mjpeg pipe:1
```

主画面 RGB 使用高清预览，缩略图 RGB 使用 640 宽预览。Depth 预览由接收端生成伪彩图。

录制保存 `rgb.mp4` 使用 H.264 copy 封装，不需要 RGB 解码；CPU 压力主要来自 Web 预览，不来自录像保存。

现场硬解检查结论：

- ffmpeg 编译支持 `vaapi`、`qsv`、`cuda` 等接口。
- 当前接收端显示为虚拟显卡 `Device 1234:1111`。
- 未发现 NVIDIA 设备。
- `/dev/dri` 未看到常见 `renderD128`。
- 未安装 `vainfo`，VAAPI 能力无法验证。

因此当前环境未开启硬件解码，也不建议直接加 `-hwaccel` 参数。若要启用硬解，需要先准备真实 GPU/核显或虚拟机 GPU 直通，再修改 `RgbPreviewDecoder` 的 ffmpeg 参数。

## 5. 后续建议

如果后续仍遇到 CPU 或内存压力：

- 降低右侧缩略图 RGB 预览 fps。
- 只对主画面启用高清 RGB 预览。
- 右侧缩略图仅显示 Depth 或较低频 RGB。
- 在接收端机器提供可用 GPU/核显后，再启用 ffmpeg 硬解。
- 开启 `sudo loginctl enable-linger fz`，保证机器开机后未登录也能自动拉起服务。
