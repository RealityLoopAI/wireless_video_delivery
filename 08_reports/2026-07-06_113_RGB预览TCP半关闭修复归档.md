# 2026-07-06 113 RGB 预览 TCP 半关闭修复归档

## 现象

- `orangepi5pro-d12a4719_cam01` 主 RGB/Depth 仍然在线，`rgb_packets` 和 `depth_packets` 持续增长。
- Web RGB 小预览间歇性 404，看起来像 RGB 画面死掉。
- 发送端日志出现 `stream=rgb_preview error=media TCP send failed: Broken pipe`。
- 发送端 `ss` 可见到接收端 `192.168.66.196:50010` 的预览 TCP 连接停留在 `CLOSE-WAIT`。

## 原因

RGB 小预览是按需发送的独立 TCP 媒体连接。接收端关闭空闲预览连接后，发送端在没有新预览帧要发时不会立刻感知对端关闭，socket 保持在 `CLOSE-WAIT`。下一次网页请求唤醒预览时，发送端先向这个已经失效的 socket 写入，触发 `Broken pipe`，之后才重连，导致网页端看到预览短暂不可用或 404。

主 RGB/Depth 连接未受影响，所以录制主链路不是这次问题根因。

## 修复

在发送端 `Transport::ensure_media_tcp_connected()` 中加入非阻塞 TCP 半关闭检测：

- 使用 `poll(..., 0)` 检查 `POLLERR`、`POLLHUP`、`POLLRDHUP`。
- 如果 socket 可读，再用 `recv(MSG_PEEK | MSG_DONTWAIT)` 判断对端是否已关闭。
- 发现半关闭后立即关闭本地 socket，并允许本次发送前直接重连。

这样预览链路从空闲恢复时不会先写入死连接。

## 注意

当前 Web RGB 预览仍是按需租约模式，设计上会在网页不请求时停止发送预览数据，这是为了降低网络占用。此修复只解决 TCP 半关闭后首包失败的问题，不改变主链路和录制格式。
