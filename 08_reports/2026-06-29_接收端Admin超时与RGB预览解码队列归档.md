# 2026-06-29 接收端 Admin 超时与 RGB 预览解码队列归档

## 背景

现场 Web 预览页偶发报错：

```text
receiver admin unavailable: timed out
```

该错误来自 `09_web_monitor/server.py`。Web monitor 会通过 HTTP 代理访问 receiver admin：

```text
http://127.0.0.1:18080
```

代理超时时间为 3 秒。因此该报错表示 Web monitor 在 3 秒内没有从 receiver admin 拿到响应，不等价于媒体 TCP 主链路完全断开。

## 根因

接收端 RGB 预览 JPEG 生成路径中，`RgbPreviewDecoder::write_packet()` 会在处理媒体包时同步把 H.264 payload 写入 ffmpeg stdin。

当 ffmpeg 子进程、pipe 或预览解码出现短时阻塞时，这个同步写入会拖慢媒体包处理路径。该路径持有 receiver 内部状态锁时，会影响 `/api/status`、`/api/preview/*` 等 admin 接口响应，最终让 Web monitor 代理请求超过 3 秒并报：

```text
receiver admin unavailable: timed out
```

本质上，这是预览解码路径对 receiver admin 响应时间造成了反压。

## 修复

修改文件：

```text
02_receiver_linux/src/main.cpp
```

核心改动：

1. `RgbPreviewDecoder::write_packet()` 不再同步写 ffmpeg stdin。
2. 新增独立 writer thread，把预览 H.264 payload 从队列写入 ffmpeg。
3. 预览队列有上限：

```text
kRgbPreviewDecoderMaxQueuedPackets = 8
kRgbPreviewDecoderMaxQueuedBytes = 4 MiB
```

4. 队列满时丢弃旧的预览包，保证预览链路不反压 receiver admin 和主录制链路。
5. `stop()` 会清空队列、唤醒 writer、关闭 pipe，并等待 writer/reader 线程退出，避免进程退出卡死。

该修复只影响 receiver 本机生成 JPEG 预览的内部调度，不改变：

- TCP media 主链路协议
- RGB/Depth packet 格式
- 录制文件格式
- frames.csv 字段
- sender 侧采集和编码逻辑

## 部署

接收端设备：

```text
192.168.66.196
```

部署方式：

1. 只同步 receiver 源码文件到接收端。
2. 在 x86 接收端本机重新编译 `gemini_receiver`。
3. 重启：

```text
gwv3-gemini-receiver.service
gwv3-web-monitor.service
```

注意：不能把 ARM 发送端机器上编译出的 `gemini_receiver` 直接拷贝到 x86 receiver 上运行，否则会出现 `Exec format error`。本次误拷贝后已恢复接收端原 x86 备份并在接收端本机重新构建。

本机 `rk3588-ubuntu cam02` 离线是因为配置相机未接入，不属于本次 receiver admin 超时问题。

## 剩余问题

本次修复后，`receiver admin unavailable: timed out` 路径没有复现。

仍观察到部分 depth 或缩略预览接口返回快速 404：

```text
/api/preview/depth -> 404
/api/preview/rgb -> 404
```

该现象表示对应预览帧没有及时生成，和 receiver admin 3 秒超时不是同一个问题。后续如继续处理，应单独检查：

1. depth 预览按需请求窗口是否太短。
2. 当前 depth 压缩格式是否全部走到了接收端伪彩生成分支。
3. sender 侧 `set_web_rgb_preview_active` 续租和 `rgb_preview_sent_packets_s` 是否持续生效。
4. Web 主画面和缩略图是否应该使用同一套 JPEG 预览缓存，避免重复链路。
