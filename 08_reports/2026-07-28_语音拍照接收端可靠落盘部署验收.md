## 3. 设备适配问题

Gemini 305 的 Orbbec SDK 帧可能在 JPEG EOI 标记后附带零填充。初次真机请求因此被 receiver 的严格 EOI 校验拒绝，未误报成功、未产生损坏图片。

修复方式：

1. sender 在发送原始 MJPEG 前仅剥离 EOI 后的零填充。
2. receiver 同时兼容尚未升级 sender 发来的同类填充报文。
3. 保存的 JPEG 有效内容不解码、不重编码。
4. 集成测试增加带 32 字节 SDK 零填充的快照报文。

## 6. 方向校正与三连拍追加验收

d12 配置 `rotation_degrees=180`。快照已改为在独立发送线程中解码、旋转 180 度并以 JPEG quality 95 重编码，不占用相机采集线程。接收端清单使用 `jpeg_rotated_180` 和 `orientation_applied_degrees=180` 标记，不再把该图片表述为原始 MJPEG。

最终验收请求：

```text
xiaohuan_photo_20260728_173243_718244_01of03
xiaohuan_photo_20260728_173243_718895_02of03
xiaohuan_photo_20260728_173243_719272_03of03
```

- 三张目标采集时间分别为 `1785231163718215 / 1785231163918215 / 1785231164118215 us`，严格相差 `200000 us`。
- 实际有效 RGB frame ID 为 `1117 / 1124 / 1131`。
- 实际 frame system timestamp 间隔约 `232.9 ms / 233.8 ms`。
- 30fps 帧周期为约 `33.3 ms`；目标附近若一帧未通过 MJPEG 完整性校验，会顺延到下一有效帧，因此实测间隔量化为约 0.233 秒。
- 三张均为标准 JFIF JPEG、`1280x800`、3 components。
- 人工查看新旧实拍图，旧图上下倒置，新三张已经旋转为正确方向。
- 三张均收到 `captured`，NAS uploader `failures=0`、`pending=0`。
- 拍照后 d12 RGB/Depth 输入和发送均约 `29.97fps`，`last_error` 已恢复为空。

语音服务默认参数为 `photo_burst_count=3`、`photo_burst_interval_seconds=0.2`。三个请求一次写入并携带目标采集时间，三张全部可靠暂存后才播放“好的，已拍照”。

## 7. 三连拍目录一致性修复

复查 NAS 后确认旧实现按每张照片各自的 `frame_system_timestamp_us` 建目录，连拍跨过整秒时会出现 `2+1` 或 `1+2` 分散到两个目录。修复后每轮语音拍照生成一个稳定 `burst_id`，三个请求分别使用 `_01of03`、`_02of03`、`_03of03`；receiver 由第一张有效帧一次性保留整组目录和文件名前缀，后两张不再重新计算目录。

自动集成测试使用跨秒时间 `xx:xx:xx.900 / 下一秒 .100 / .300`，并先在同一秒写入一张普通照片制造目录冲突。结果三张仍统一落入新分配的同一目录，文件名依次为 `.jpg`、`_001.jpg`、`_002.jpg`，四个 staged 任务全部返回 `captured`，`failures=0`。

实机部署后在 d12 于时间小数部分 `824359us` 发起三连拍，三个目标采集时刻跨过下一整秒。三条 `captured` 回执均指向：

```text
/home/fz/Desktop/nas/voice_photos/orangepi5pro-d12a4719_cam01/2026-07-28/17-52-22/
  20260728_175222.jpg
  20260728_175222_001.jpg
  20260728_175222_002.jpg
```

三张均为有效 JFIF JPEG、`1280x800`，大小分别为 `201164 / 201047 / 201006 bytes`。receiver 为 `enqueued=3`、`completed=3`、`failures=0`；NAS uploader 为 `pending=0`、`failures=0`。

验收期间发现 d12 有两个历史远程测试 Python 死循环各占满一个 CPU 核，导致 SoC 温度约 85°C、发送帧率短时降到约 18fps。这两个进程与业务服务无关，清理后 RGB/Depth 输入及发送均恢复约 `29.91fps`，`last_error` 为空。
