# 2026-06-29 接收端托管与 Wi-Fi 省电优化归档

## 背景

现场检查网络时发现：

1. 接收端 `192.168.66.196` 上 receiver 和 Web monitor 进程实际在运行，但 systemd 状态异常：
   - system 级 `gwv3-gemini-receiver.service` 不存在。
   - system 级 `gwv3-web-monitor.service` 为 inactive。
   - 实际运行进程没有处在预期的 systemd user service 管理状态中。
2. 本机发送端 `192.168.66.85` 的 Wi-Fi power save 为 `on`。
3. 控制端到 receiver、receiver 到本机发送端出现过 100ms 到数百 ms 的延迟尖峰。

该状态会带来两个问题：

- 接收端进程异常退出或端口残留时不能稳定自动恢复。
- Wi-Fi 省电会让实时媒体链路出现延迟尖峰，影响 Web 预览和 UDP/TCP 实时发送稳定性。

## 本次现场操作

### 1. 接收端纳入 systemd user service

接收端确认：

```text
systemctl --user 可用
Linger=yes
```

执行接收端自启动安装：

```text
./05_tools/install_receiver_autostart.sh 06_configs/receiver_ubuntu-01.json
```

安装后状态：

```text
gwv3-gemini-receiver.service       enabled active
gwv3-web-monitor.service           enabled active
gwv3-receiver-log-rotate.timer     enabled active
```

进程 cgroup 确认：

```text
gemini_receiver -> gwv3-gemini-receiver.service
uvicorn/server.py -> gwv3-web-monitor.service
```

监听端口确认：

```text
50010/tcp   media TCP fallback
50011/udp   status
50012/udp   clock sync
50013/udp   media UDP
18080/tcp   receiver admin, 127.0.0.1 only
8080/tcp    Web monitor
```

### 2. 关闭发送端 Wi-Fi 省电

本机发送端：

```text
iw dev wlan0 set power_save off
nmcli connection modify '土著拯救器-5G' 802-11-wireless.powersave 2
```

同步 `05_tools/sender_wifi_guard.sh` 到：

```text
192.168.66.133:/home/orangepi/Desktop/wireless_video_delivery
192.168.66.206:/home/orangepi/Downloads/wireless_video_delivery
```

并在两台 Orange Pi 上执行新的 Wi-Fi guard，确认：

```text
Power save: off
wlan0 connected: 666666-5G
```

## 代码加固

### 1. `05_tools/sender_wifi_guard.sh`

新增启动时关闭 Wi-Fi 省电：

```text
gemini_sender_wifi_disable_powersave
```

默认启用，可通过以下环境变量关闭：

```text
GEMINI_SENDER_WIFI_DISABLE_POWERSAVE=0
```

该函数会尽量执行：

```text
iw dev <iface> set power_save off
nmcli connection modify <active_connection> 802-11-wireless.powersave 2
```

失败不阻断 sender 启动，但会尽量把当前连接和 NetworkManager 配置都改成禁用省电。

### 2. `05_tools/stop_receiver.sh`

停止 receiver 时，除了 user service 和 PID 文件，还会清理同仓库路径下的残留：

```text
12_build/bin/gemini_receiver --config
```

避免手工启动进程继续占用 `50010/18080/50013` 等端口。

### 3. `05_tools/install_receiver_autostart.sh`

安装自启动服务前，先停止 user service，再清理同仓库残留的：

```text
09_web_monitor/.venv/bin/python -m uvicorn server:app
12_build/bin/gemini_receiver --config
```

这样即使现场之前手工启动过 receiver/web monitor，安装脚本也不会因为端口被旧进程占用而生成失败服务。

## 当前结论

1. 接收端托管已恢复为 user systemd，后续异常退出可自动重启。
2. 三台发送端 Wi-Fi power save 已关闭，延迟尖峰明显收敛。
3. 当前三路媒体总入站约 46Mbps，网络本身没有满载。
4. 本机 `rk3588-ubuntu cam02` 仍离线，原因是配置 serial `AY2MC31010W` 的相机未接入；这和网络优化无关。

## 后续建议

1. 保持所有发送端启动脚本走 `sender_wifi_guard.sh`，不要绕过它直接启动 sender。
2. 如果后续新增 AP/CPE，优先按发送端分摊空口，而不是把全部设备挤在一个 5GHz BSSID。
3. Web/status 后续仍建议增加每路实时 fps、Mbps、UDP 丢包率和 TCP 队列字段，减少现场依赖 SSH 手工排查。
