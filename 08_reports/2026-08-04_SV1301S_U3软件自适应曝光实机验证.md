# SV1301S_U3 软件自适应曝光实机验证

日期：2026-08-04

## 1. 问题与根因

第一版软件自适应曝光只允许 Gemini 305 启用。本机 `rk3588-ubuntu/cam01` 实际连接的是 `SV1301S_U3`，因此型号保护逻辑没有创建曝光控制器，正式配置也仍是固定手动曝光 `312/0`。

本次没有直接取消型号保护，而是先测量 SV1301S_U3 的 SDK 属性和 30fps 边界，再将该型号加入显式支持列表。

## 2. 设备与 SDK

- sender：`rk3588-ubuntu`
- camera：`SV1301S_U3`
- firmware：`RD3013`
- serial：`AY2M54302ZH`
- Orbbec SDK：`1.10.27`
- USB：USB 3.x
- RGB：`1920x1080@30 MJPG`
- Depth：`320x200@30 Y12`

SDK 查询到的 RGB 属性范围：

- exposure：`1..5000`，默认 `157`
- gain：`0..100`，默认 `0`
- power-line frequency：`0..2`，当前固定为 `1`
- auto white balance：支持并保持开启

SDK 属性的可写上限不是 30fps 的安全上限，不能直接把 exposure 放到 5000。

## 3. 30fps 曝光边界

在正式 RGBD 档位下逐项测试 exposure：

| exposure | RGB 实测结果 |
| ---: | --- |
| 300 | 约 30fps |
| 312 | 约 30fps |
| 325 | 约 30fps |
| 333 | 约 30fps |
| 334 | 约 30fps |
| 350 | 约 27fps |

正式上限保守取 `325`，为 USB、场景和设备个体波动留出余量。配置校验会拒绝 SV1301S_U3 的 `exposure_max > 325`。

## 4. 正式配置

本机配置启用源 MJPEG 测光闭环：

```json
{
  "enabled": true,
  "interval_ms": 500,
  "exposure_min": 80,
  "exposure_max": 325,
  "gain_min": 0,
  "gain_max": 20,
  "target_p95_luma": 190,
  "luma_deadband": 8,
  "highlight_luma": 245,
  "max_highlight_fraction": 0.005,
  "underexposed_samples": 3,
  "roi_margin_percent": 10
}
```

相机原生自动曝光保持关闭，软件控制器只在 500ms 测光周期调整 SDK 的手动 exposure/gain，不阻塞采集、编码和发送线程。

首轮沿用 Gemini 305 的 P95=200、高光比例 0.25% 时，场景 P95 约 190、零星高光约 0.29%，会触发不必要的 gain 回退。SV1301S_U3 因此使用独立目标 P95=190、高光比例 0.5%。

## 5. 部署后结果

重启正式服务后，日志确认：

- `adaptive_exposure=enabled`
- 控制值从 `312/0` 收敛到 exposure `325`、gain `12..16`
- 当前 P95 约 `194`
- 高光比例约 `0.34%`
- `adaptive_failures=0`
- RGB/Depth 输入与发送均约 `29.9..30fps`
- RGB 坏帧、时间绑定丢帧和编码器滞后重置均为 0
- 本机温度约 `54.5..57.3 C`

接收端预览接口返回实时 `320x180 JPEG`，画面内容正常。验证期间接收端媒体 TCP 曾出现约 2 秒反压，产生短时发送失败，随后自动恢复到 30fps；该事件与曝光控制无因果关系。

## 6. 当前边界

这次完成了属性边界、配置校验、控制器单测、配置回归和数分钟实机运行验证。它能处理一般明暗场景变化并保护 30fps，但不等同于跨昼夜长测；极端逆光、频闪灯源和长时间温漂仍应通过后续现场录制观察。
