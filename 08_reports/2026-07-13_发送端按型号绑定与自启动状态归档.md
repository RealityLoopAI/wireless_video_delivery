# 发送端按型号绑定与自启动状态归档

日期：2026-07-13

## 现象与根因

`orangepi5pro-ab748372` 和 `orangepi5pro-fe0ec3fe` 重启后 systemd 服务均已自动启动且 `NRestarts=0`，但两台物理相机被有意互换。旧配置严格绑定序列号，sender 因 `configured camera not found` 保持状态线程运行而不采集媒体，因此接收端表现为没有自启动。

进一步检查发现配置模板中的 `device_model` 过去没有进入 `CameraConfig`，解析器会忽略该字段。仅删除 `serial_number` 会退化为按 `device_index` 选择，不是真正的型号绑定。

## 实现

1. `CameraConfig` 新增并解析 `device_model`，限制长度并拒绝控制字符。
2. Orbbec SDK 枚举阶段读取 SDK 设备型号并执行精确匹配。
3. `uid` 或 `serial_number` 非空时保留严格绑定，同时把型号作为附加约束。
4. 序列号和 UID 均缺省时按型号选择；型号唯一时接受任意物理序列号，多个同型号设备时使用显式 `device_index`。
5. 热插拔身份判断、设备枚举错误信息、camera announce 和启动日志均加入型号信息。
6. `sender_preflight.sh` 显示配置型号，避免把 `serial=未指定` 误判为完全无约束。
7. 新增非法型号配置测试，全部 sender 配置继续参与统一校验。

多相机配置仍要求每路提供 `serial_number` 或 `uid`。这是必要限制：同一发送端上的多台同型号相机仅靠型号无法稳定映射到不同 `camera_id`。
