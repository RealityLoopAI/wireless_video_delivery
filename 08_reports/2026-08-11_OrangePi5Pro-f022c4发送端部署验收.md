新机镜像初始复用了其他 Orange Pi 的 hostname 和 `/etc/machine-id`。部署时已重新生成
machine-id，并使用板载有线 MAC 尾号生成固定主机名和 sender_id，避免与
`orangepi5pro-d12a4719` / `orangepi5pro-fe0ec3fe` 发生身份冲突。

## 部署内容

1. 安装 CMake、OpenCV、GStreamer、jsoncpp、zlib、lz4 等 ARM64 构建依赖。
2. 同步当前 sender 源码、Orbbec SDK 1.10.27、配置和管理脚本。
3. 在新机本地使用 GCC 11.4 / CMake 3.22 构建 `gemini_sender`。
4. 安装 Orbbec udev 权限和 USB 禁用休眠规则。
5. 安装并启用 `rk3588-usb-prepare.service`，将 `usbfs_memory_mb` 设为 256，将 TCP 发送缓冲上限设为 32 MiB。
6. 安装并启用 `gwv3-gemini-sender.service`，包含 watchdog、相机断线重连和开机自启。
7. 关闭 Wi-Fi 省电，当前连接 `666666-5G` 5 GHz。
8. chrony 改为只跟随接收端 `192.168.66.196`。

## 相机配置

相机 USB 设备为 RGB `2bc5:0511` + Depth `2bc5:0614`，SDK 型号是 `SV1301S_U3`，
与现有 `fe0ec3fe` / `ab748372` 相同。正式配置为：

- 只按型号绑定，不绑定物理序列号。
- RGB：`1920x1080@30 MJPG`。
- Depth：`320x200@30 Y12`。
- RGB 编码：Rockchip MPP H.264，12 Mbit/s。
- Depth 传输：zlib。
- 手动曝光 `312`，gain `0`，自动白平衡。
- Web RGB 预览按需开启，30 FPS，500 kbit/s。
- 相机热插拔扫描开启。

首次启动时 Depth 只枚举在 480M USB2，但仍能跑满 30 FPS。重启验收时 Depth
已进入 Bus 06 `5000M USB3`，RGB 保持在 USB2 companion bus，与同型相机的正常枚举结构一致。

## 验收结果

- 重启后 hostname、machine-id 和 sender_id 均保持。
- chrony 同步源为接收端，重启后 system time correction 约 0.68 ms。
- `gwv3-gemini-sender.service`、`rk3588-usb-prepare.service`、`chrony.service` 均为 enabled + active。
- 开机时相机延迟枚举约 20 秒，watchdog 自动重建子进程后恢复，systemd `NRestarts=0`。
- 稳定期 RGB/Depth 输入和发送约 29.9--30 FPS，丢帧、发送失败均为 0。
- sender 约占用半个 CPU 核心，RSS 约 88 MiB，芯片温度约 46 C。
- Wi-Fi 信号约 -35 dBm，协商速率在现场样本中为 RX 433 / TX 195 Mbit/s。
- CLOCK_SYNC 有效，重启后现场 offset 约 -1.15 ms，delay 约 1.49 ms。
- RGB 和 Depth 预览可生成，画面方向正常。

## 已知限制

SDK 对 `1920x1080 RGB + 320x200 Depth` 组合会输出 `Can not find matched camera param`，
接收端的实时 `calibration_available` 为 false。这与现有同型 SV1301S_U3 设备行为一致，
不影响 RGB/Depth 采集、时间戳、传输和录制，但下游不应把该路径中的 calibration JSON
误当作已验证的 RGBD 几何对齐参数。
