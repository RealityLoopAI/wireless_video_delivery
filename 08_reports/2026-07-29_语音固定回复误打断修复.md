# 语音固定回复误打断修复

日期：2026-07-29

## 现象

用户说“你好小环”后，音箱回复“我在，有什么可以帮到您的”，但播放到“有什”附近会被提前终止。

## 原因

d12 的 USB 麦克风当前为 100% 捕获增益、AGC 开启，能够强烈收到 USB 音箱回声。运行日志中：

```text
wake matched: 你好 小环 -> 我在
playback command candidate ... rms=0.51 text=我 拍照 matched=True
```

正常环境噪声 RMS 约为 0.004，回复回声达到 0.48 至 0.57。原来的 `barge-in` 会在回复播放时运行受限拍照语法；Vosk 被小语法约束后把回复回声识别为“我 拍照”或“照”，程序随即终止当前播放并错误启动三连拍。

当前硬件没有把音箱播放 PCM 作为回声消除参考输入，无法可靠区分“用户在回复期间说拍照”和“音箱自身回声”。

## 修复

1. `barge_in` 生产默认值由 `true` 改为 `false`。
2. `run_wake_service.sh` 显式传入 `--no-barge-in`，避免默认值变化导致现场行为回退。
3. 固定回复播放期间不再运行拍照识别，也不会主动终止播放。
4. 回复完整结束后忽略 0.3 秒尾音，再开启 8 秒拍照命令窗口。
5. “拍照”命令命中后的即时反馈与后台三连拍逻辑保持不变。

## 当前交互

```text
用户：你好小环
设备：我在，有什么可以帮到您的
用户：拍照
设备：好的，已拍照
```

如后续要恢复播放中打断，需要先引入带播放参考信号的 AEC，再重新验证误触发率；只调高音量阈值不能可靠解决当前回声问题。
