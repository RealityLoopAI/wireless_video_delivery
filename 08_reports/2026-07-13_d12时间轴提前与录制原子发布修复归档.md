# d12 时间轴提前与录制原子发布修复归档

日期：2026-07-13

## 1. 现象与定位

问题输出：

```text
web_fusion_outputs/2026-07-13_fz_007_0001_global_timestamp_us/d42023ad5560
```

该任务中 `orangepi5pro-d12a4719_cam01` 的同步时间匹配正常，但画面稳定提前。逐行比较任务的 `sync_matches.csv` 与录制收尾后的最终 `frames.csv`，得到：

```text
d12 video_index - rgb_video_frame_index = +20 frames
30 FPS 下对应约 666.7 ms
```

任务在 18:27:57 创建，接收端在 18:28:53 才完成媒体收尾和最终 CSV 合并。任务读取了录制中的实时 CSV，并用 RGB 行号推导 MP4 帧号。d12 启动阶段有 20 个尚未进入可解码 MP4 的 RGB 包，最终收尾时这些行被删除，因此后续画面统一错取了 20 帧之后的内容。

CLOCK_SYNC 不是本次根因。d12 本段 2835 帧全部有效，offset 约为 0.96-1.12 ms，首尾变化约 0.08 ms；`global_timestamp_us` 单调，采集到时间戳绑定耗时中位数为 27 us。

## 2. 接收端修复

接收端改为三阶段发布：

```text
frames.csv.inprogress  # 录制中的内部日志，下游不可见
frames.csv.finalizing  # 已合并实际 RGB 落盘索引，尚未发布
frames.csv             # 媒体收尾后原子发布的正式文件
```

发布顺序：

1. 停止接收新录制数据并刷新队列。
2. 关闭临时 CSV。
3. 将实际录入 MP4 的 RGB 帧索引合并到 finalizing CSV。
4. 关闭并校验 MP4/MKV。
5. 原子重命名发布最终 `frames.csv`。
6. 写 `meta.json`，设置 `closed=true`、`frames_publish_state=finalized`。
7. 最后原子发布 `recording_ready.json`。

因此旧版下游脚本即使仍按文件名扫描，也无法在录制中取得正式 `frames.csv`，最多明确失败，不会再静默生成错误视频。

## 3. 下游修复

新增 `05_tools/sync_input_guard.py`，开始同步前检查：

1. `meta.closed=true`。
2. 新数据的 `frames_publish_state=finalized`。
3. `meta` 声明 ready 文件时，标志必须存在且 `ready=true`。
4. CSV 必须包含 `rgb_recorded`、`rgb_video_frame_index`、`global_timestamp_us`。
5. 只读取 `stream_type=rgb && rgb_recorded=1`。
6. `rgb_video_frame_index` 必须从 0 连续递增。
7. `global_timestamp_us` 必须严格单调。
8. 可选用 ffprobe 核对 MP4 解码帧数与 CSV 帧数。

下游 `sync_multi_segments.py` 的关键规则：

```python
if row["stream_type"] != "rgb" or not parse_bool(row["rgb_recorded"]):
    continue
video_index = int(row["rgb_video_frame_index"])
```

禁止继续使用：

```python
video_index = len(rows)
```

## 5. 使用方式

停止录制并等待 receiver 完成收尾后运行：

```bash
python3 05_tools/sync_input_guard.py \
  --inputs <camera_1_segment> <camera_2_segment> ... \
  --verify-video-frames
```

Windows Web 任务使用 YAML 时：

```powershell
python E:\Sync_video\new_sync\sync_input_guard.py `
  --config <sync_job_config.yaml> `
  --verify-video-frames
```

校验返回非零时不得启动 `sync_multi_segments.py`。历史错误任务 `d42023ad5560` 应作废，并在所有输入最终化后重新生成。

下游 Windows 交付包位于控制端桌面：

```text

```

其中包含修复版脚本、独立输入校验器、源代码补丁和本归档说明。

## 6. 精度边界

该修复消除的是“时间行到 MP4 帧号映射错误”。没有硬件触发线时，各相机仍为自由运行，30 FPS 下内容级残余通常落在一个帧周期内；本次 d12 与其他设备最近时间戳 P95 约为 16 ms。该残余不能通过修正视频行号完全消除，后续仍可使用固定内容偏移标定或硬件同步。
