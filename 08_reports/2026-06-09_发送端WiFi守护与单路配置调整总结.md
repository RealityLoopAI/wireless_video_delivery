# 发送端 Wi-Fi 守护与单路配置调整总结 2026-06-09

## 1. 范围

本次调整覆盖：

```text
RK3588 / Orange Pi 当前单路默认配置
发送端启动脚本、预检脚本、watchdog 的 Wi-Fi guard 行为

```


## 2. 本次已落地改动

### 2.1 Wi-Fi guard 不再默认硬编码单一 SSID

此前问题：

```text
启动脚本和 watchdog 默认写死土著拯救器-5G
现场换 Wi-Fi 后，脚本可能在启动前或运行中误判并尝试切回旧网络
```

当前行为：

```text
默认不再强制指定 SSID
默认只要求 wlan0 当前频率不低于 5000MHz
仍保留通过环境变量显式绑定现场 Wi-Fi 的能力
```

相关环境变量：

```bash
GEMINI_SENDER_DEFAULT_WIFI_CONNECTION=现场5G网络名
GEMINI_SENDER_WIFI_CONNECTION=现场5G网络名
GEMINI_SENDER_WIFI_REQUIRED_SSID=现场5G网络名
GEMINI_SENDER_WIFI_MIN_FREQ_MHZ=5000
GEMINI_SENDER_WIFI_IFACE=wlan0
```

### 2.2 Wi-Fi 链路检查增加 `nmcli` fallback

此前问题：

```text
Wi-Fi guard 主要依赖 iw
若现场设备缺少 iw，链路检查可能误报失败
```

当前行为：

```text
优先使用 iw
若 iw 不存在，则回退到 nmcli 获取当前 SSID 和频率
```

### 2.3 当前单路配置身份字段调整为 auto 派生

当前配置文件：

```text
06_configs/sender_rk3588-01_one_camera.json
```

当前身份字段：

```text
sender_id: auto
camera_id: cam02
```

在当前机器上，预检实际派生为：

```text
sender_id: orangepi5pro-c973b736
camera_key: orangepi5pro-c973b736_cam02
```

说明：

```text
这样可避免继续使用临时手工 ID
也避免与接收端已有 live sender_id/camera_id 冲突
```

### 2.4 当前单路颜色控制参数更新

当前参数：

```text
auto_exposure=false
exposure=333
gain=80
```

原因：

```text
此前尝试继续提高 gain，但现场相机实际回报值稳定在 80
因此保持 gain=80，并用更高的 exposure 提升亮度
```

### 2.5 文档同步

已同步文档中的两类信息：

1. Wi-Fi guard 默认策略已改为：

```text
默认只保 5GHz
SSID 绑定改为可选环境变量
```

2. 当前单路发送配置不再以旧固定 sender_id 作为默认描述。

## 4. 当前运行结论

当前发送端重启后，预检输出中的 Wi-Fi guard 已变为：

```text
wifi_guard: iface=wlan0 connection=未配置 required_ssid=未配置 min_freq_mhz=5000
```

这表示：

```text
默认不强制旧 SSID
现场换网络后，只要仍在 5GHz，发送端不会因为旧 SSID 策略卡住
```

## 5. 剩余注意事项

1. 多发送端同时在线时，仍会共享同一接收端与 Wi-Fi 资源。
2. 当前 Wi-Fi guard 问题已缓解，但不代表网络吞吐本身一定足够。
3. 若现场确实需要只允许某一个 SSID，应显式设置 `GEMINI_SENDER_DEFAULT_WIFI_CONNECTION` 或 `GEMINI_SENDER_WIFI_*`。
